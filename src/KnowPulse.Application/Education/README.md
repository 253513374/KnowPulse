# EDU-M1 学校与教学关系基础

本节保留最初学校基础切片的边界说明。当前学校网页、成员导入、教材、测评及评语实现另见根目录 `docs/education-implementation-progress.md`，不能将下文历史“尚未包含”直接当作当前源码状态。

学校是当前 tenant 内的独立实体，不复用 Department，也不假定一个学校等于一个 tenant。复用现有 IdentityUser；只有同 tenant 的有效账号能进入关系。创建学校需要独立 `SchoolCreate` 权限，同时给创建者建立该校 Manager membership。后续管理需 `SchoolManage` 与该校当前有效 Manager membership 同时满足，平台功能权限与 admin 角色均不能替代学校身份。

本轮可逆实现选择：

- 班级按学校、学期建档，7–9 年级保存为该学期快照；下一学期创建新记录，不修改历史年级。学期、班级、学科不提供删除或改变历史关联键的入口。
- 学科 Code 在 tenant 内统一并规范为大写。学校管理员可创建租户公共学科目录；相同 Code/Name 返回原记录，不提供影响其他学校的改名、删除入口。
- Teacher/Student/Manager 是分别记录的学校身份；一个用户可同时有多种身份。区间均为 UTC 半开 `[from,to)`，相邻边界不重叠。授课和在班区间限定在对应学期，空结束时间规范为该学期结束时间，且必须被一条同校对应身份记录完整覆盖。
- 同校同生的任何在班重叠均拒绝；多个教师可共同承担同班同科。相同关系与区间的顺序重试返回原记录。同一关系的重叠副本拒绝。变动通过结束旧记录、创建新记录完成，禁止延长已结束区间或覆盖教师、学生、班级、学科。
- 结束学校身份前须先结束依赖的授课/在班关系，避免留下超出身份期限的授权事实；结束管理员身份必须已有另一管理员覆盖结束时点，防止学校失去管理入口。这里是技术防锁死约束，生产人员交接、争议处理政策仍需确认。
- 所有校内配置写命令先完成授权与引用校验，再递增 School.ConfigurationRevision；它与 ABP ConcurrencyStamp 都是 EF 并发令牌。并发校内写冲突要求重新提交，重试后重新校验重叠。关系和校记录的写入依赖生产关系型 UoW 事务；SQLite 负向测试不等于已验证 PostgreSQL 并发和事务语义。
- 读取学校 roster 与关系必须为该校管理员，支持分页与有效时点查询；GetMySchools 仅返回当前账号的当前有效学校身份，结束后保留历史事实但不再出现在有效学校列表。

这是服务端基础，尚未包含学校导入、账号邀请/开通/合并、跨 tenant 转校、微信身份绑定、教育管理 UI、真实学校/教材数据或完整教育教学闭环。总权限注册、DbContext 挂接和迁移由主实施任务完成，后续教学授权消费者还需接入有效任教/在班关系。

## 学生评语边界

`EducationFeedbackAppService` 使用独立的 `FeedbackManage`/`FeedbackView` 功能权限并复用 `EducationAssessmentAccessGuard` 的账号、任教和在班核验。私有观察与单人评语分别存储；所有测评关联逐项等待当前正式发布的完整讲评，学生使用独立裁剪契约。发布、版本阅读和无正文通知是三个事实，微信投递不是该服务的完成依据。实现决策见根目录 `docs/adr/0018-private-observations-and-versioned-student-feedback.md`，个人常用语和完整分析/方案仍须后续实施。
