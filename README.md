# KnowPulse

KnowPulse 是教师工作后台与学生答题工具，基于 ABP Framework、ASP.NET Core、Blazor、PostgreSQL、MinIO、Qdrant 和 LiteLLM。

当前产品主线是：教师整理个人资料或选择获授权共享资料，生成并确认题目，从自己的学生名单选择接收人发布答题任务；学生在微信小程序作答，教师查看本人任务的结果。教师通过 `/teacher/materials`、`/teacher/shared`、`/teacher/questions`、`/teacher/students` 和 `/teacher/tasks` 完成日常操作。

学校管理、学校成员身份、任教／在班核验及旧 `/education/*` 工作区已退出产品流程。师生关系采用邀请码申请和教师确认，不要求学校、班级或教师资质认证；登录、租户隔离、资料归属和任务权限继续独立校验。历史学校教育文档仅供追溯，当前范围以[业务需求](docs/business-requirements.md)为准。

学生端使用平级独立仓库 [KnowPulse.MiniProgram](../KnowPulse.MiniProgram/README.md)，只保留答题与本人教师关联流程。本仓库原内嵌 `miniprogram/` 学校小程序已退役并删除。

## About this solution

This is a layered startup solution based on [Domain Driven Design (DDD)](https://abp.io/docs/latest/framework/architecture/domain-driven-design) practises. All the fundamental ABP modules are already installed. 

### Pre-requirements

* [.NET 10.0+ SDK](https://dotnet.microsoft.com/download/dotnet)
* [Node v20.11+](https://nodejs.org/en)

### Configurations

The solution comes with a default configuration that works out of the box. However, you may consider to change the following configuration before running your solution:

* Check the `ConnectionStrings` in `appsettings.json` files under the `KnowPulse.HttpApi.Host` and `KnowPulse.DbMigrator` projects and change it if you need.

#### 千问 Embedding 配置

资料处理通过 LiteLLM 调用千问 `text-embedding-v4`，输出固定为 1536 维。主、备用 alias 均使用同一模型，聊天出题使用 LiteLLM 模板中的 OpenAI 配置，密钥通过 `OPENAI_API_KEY` 注入。

在后端仓库根目录的本地 `.env` 填写 `DASHSCOPE_API_KEY`，不要提交或放入 API Host／小程序。`DASHSCOPE_API_BASE` 默认为 `https://dashscope.aliyuncs.com/compatible-mode/v1`（北京地域）；其他地域或业务空间专属域名按[阿里云官方接口说明](https://help.aliyun.com/zh/model-studio/embedding-interfaces-compatible-with-openai)配置，与密钥所属地域保持一致。填写后执行：

```powershell
docker compose up -d --no-deps litellm
```

配置使用新集合 `knowledge_chunks_qwen_v4_1536`，不删除或混用原集合；已有资料需要创建新的处理任务。已有数据库的模型目录与用途绑定属于持久化设置，应在维护页 `/rag/models` 同步 Embedding 业务版本 `2026-10-qwen-embedding-v4-1536`；仅修改 appsettings 不会覆盖已保存的绑定。当前隔离验证环境使用单独的千问集合，详见[验证记录](docs/teaching-core-verification.md)。

Qdrant 服务端 `QDRANT__SERVICE__API_KEY` 与应用端 `KNOWPULSE_QDRANT_API_KEY` 必须一致。示例仅提供开发值，本机验证已使用独立随机值；真实值仍放在本地 `.env`。API Host 启动前须将 `KNOWPULSE_LITELLM_API_KEY`、`KNOWPULSE_QDRANT_API_KEY` 注入进程环境，仓库 `.env` 不会由 `dotnet run` 自动加载。

#### 微信小程序登录配置

后端 API Host 已自动加载项目目录下的 `appsettings.secrets.json`。在后端仓库 `KnowPulse/` 根目录执行以下命令，从模板创建本地配置；已有文件会保留：

```powershell
if (-not (Test-Path .\src\KnowPulse.HttpApi.Host\appsettings.secrets.json)) {
    Copy-Item .\src\KnowPulse.HttpApi.Host\appsettings.secrets.example.json .\src\KnowPulse.HttpApi.Host\appsettings.secrets.json
}
```

编辑 `src/KnowPulse.HttpApi.Host/appsettings.secrets.json`，填入同一个微信小程序的 AppID 和 AppSecret；若已有其他配置，只合并下面的 `WeChat` 节：

```json
{
  "WeChat": {
    "MiniProgram": {
      "AppId": "填写你的小程序 AppID",
      "AppSecret": "填写你的小程序 AppSecret"
    }
  }
}
```

保存后重启 API Host：

```powershell
dotnet run --project .\src\KnowPulse.HttpApi.Host
```

- 后端 `AppId` 必须与平级小程序工程 `KnowPulse.MiniProgram/project.config.json` 中的 `appid` 一致；API 地址在该工程的 `miniprogram/config.js` 中配置。
- `appsettings.secrets.example.json` 只保留空值模板；真实密钥只填入 `appsettings.secrets.json`。该文件已加入 `.gitignore`，不要提交到 Git 或放入小程序代码。
- 仓库根目录的 `.env` 不会自动加载到 API Host，不要只把微信配置写在 `.env` 中。

### Before running the application

#### Generating a Signing Certificate

In the production environment, you need to use a production signing certificate. ABP Framework sets up signing and encryption certificates in your application and expects an `openiddict.pfx` file in your application.

This certificate is already generated by ABP CLI, so most of the time you don't need to generate it yourself. However, if you need to generate a certificate, you can use the following command:

```bash
dotnet dev-certs https -v -ep openiddict.pfx -p 62dab894-8f5a-4b93-bfbd-d881fb38b98b
```

> `62dab894-8f5a-4b93-bfbd-d881fb38b98b` is the password of the certificate, you can change it to any password you want.

It is recommended to use **two** RSA certificates, distinct from the certificate(s) used for HTTPS: one for encryption, one for signing.

For more information, please refer to: https://documentation.openiddict.com/configuration/encryption-and-signing-credentials.html#registering-a-certificate-recommended-for-production-ready-scenarios

> Also, see the [Configuring OpenIddict](https://abp.io/docs/latest/deployment/configuring-openiddict#production-environment) documentation for more information.

#### Install Client-Side Libraries

Run the following command in the directory of your final application:

```bash
abp install-libs
```

> This command installs all NPM packages for MVC/Razor Pages and Blazor Server UIs and this command is already run by the ABP CLI, so most of the time you don't need to run this command manually.

#### Create the Database

Run `KnowPulse.DbMigrator` to create the initial database. This should be done in the first run. It is also needed if a new database migration is added to the solution later.

### Solution structure

This is a layered monolith application that consists of the following applications:

* `KnowPulse.DbMigrator`: A console application which applies the migrations and also seeds the initial data. It is useful on development as well as on production environment.
* `KnowPulse.HttpApi.Host`: ASP.NET Core API application that is used to expose the APIs to the clients.
* `KnowPulse.Blazor`: ASP.NET Core Blazor Server application that is the essential web application of the solution.
