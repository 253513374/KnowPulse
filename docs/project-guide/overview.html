KnowPulse 项目导读

KnowPulse 把企业知识发布、权限感知问答、人工审题、考试和个人学习连成一个闭环。管理与业务主系统是 ABP 分层单体；同级微信小程序目前是独立交互原型，尚未接入真实业务。

基准：2026-10-19，后端提交 31c5e6f。本目录描述当前代码；早期 MVP 文档保留各自阶段语境。

系统架构与运行边界

运行架构

Web 宿主和 API 宿主分别启动。业务服务、索引 worker 和认证服务在 API 宿主内；业务领域没有拆成微服务。小程序虚线表示后续接入方向。

Web 当前使用 AddInteractiveWebAssemblyComponents 与 AddInteractiveWebAssemblyRenderMode。旧 README 的“Blazor Server”表述不足以准确说明当前渲染方式；不能把 Blazor.Client 当成单独的业务后端。

编译依赖

箭头表示 .csproj 的项目引用，方向为“依赖方 → 被依赖方”，不是 HTTP 调用方向。图中不展开 ABP NuGet 内部依赖。

运行时由 API Host 组合 Application、EntityFrameworkCore 和 HttpApi。Domain 不引用 Application；EF 仓储由宿主注入。HTTP API 同时存在显式控制器和 ABP 自动生成的约定控制器，因此“没有手写 Controller”不等于“没有公开接口”。

一次登录与业务请求

认证回答“你是谁”；ABP 功能权限回答“能否操作这个功能”；知识可见范围与考试/路径分配回答“能否访问这个对象”。菜单隐藏只改善界面体验，服务端校验才是权限边界。

外部依赖与故障影响

依赖 数据职责 不可用时影响
PostgreSQL 用户、组织、知识版本、索引任务、分块、题库、考试、学习与审计 大部分业务读写和认证受影响
MinIO 版本附件 Blob；元数据保存在 PostgreSQL 上传、下载、附件解析失败；纯正文不依赖附件读取
Qdrant 向量与权限快照，用于候选召回 索引失败；检索失败时问答返回保守结果并记录阶段
LiteLLM Chat 与 Embedding 的统一模型入口 Embedding 失败影响索引/检索；已有授权片段时 Chat 失败可返回带来源的降级回答
MarkItDown 将配置支持的文档转为 Markdown 可转换附件在 reader 阶段失败；直接文本读取不经过转换器

PostgreSQL 和 MinIO 是备份重点。Qdrant 是可重建索引；模型调用费用、耗时与健康检查需要看应用审计和网关状态。代码中存在费用估算字段，但不能把字段存在视为准确计费已经实现。

本地部署边界

Compose 当前只定义依赖服务，未定义 Web/API 应用容器。这里的端口是本地默认值，可由环境变量覆盖；生产入口、HTTPS、证书、secret 注入、备份和反向代理按原有部署手册实施。当前源码与 Compose 没有把 Redis、RabbitMQ、Kafka 或 Hangfire 配置成该业务链路的必需组件；索引队列实际由数据库任务表和进程内 worker 构成。

  • Web 渲染模式、浏览器端 OIDC。
  • 项目引用、HTTP 代理。
  • 基础设施配置、PostgreSQL 配置。

核心业务流程

返回导读

知识发布与异步索引

界面通过 API 查询任务状态。附件保存早于原子发布，Blob 不参与关系型数据库事务；发布失败后保留可修复草稿。旧 PublishVersionAsync 为兼容调用会在空策略时补全员规则，新引导走显式策略入口。

发布成功表示版本、访问策略和待执行任务已经保存。可检索还需要摄取、Embedding、向量写入全部成功，并通过检索时的状态和权限复核。

源码：上传引导、发布服务、原子发布 ADR。

索引执行与恢复

这是阶段主线，其他阶段异常也会标记失败。当前分块目标为 1,200 字符，重叠 120 字符；这是字符策略，不是语义分块。worker 默认每 5 秒轮询、每批最多 5 项、逐项处理，配置可覆盖。

标有“派生新任务”的边表示 RetryOfJobId 来源关系，不是把原记录直接改回 Pending。自动失败重试复用原任务，延迟按指数增长，上限 30 分钟；默认最大重试次数为 3。恢复入口先把原任务记为失败再创建新任务；源码没有据此证明已经中断原执行进程，不能把它当作强制取消能力。

正文和 .txt/.md/.markdown 可直接处理；PDF、Office 等依赖启用且可用的 MarkItDown。当前 reader 遇到不支持的附件会让任务失败，不会自动跳过图片、视频或压缩包。混合附件需特别检查；“仅附件”不等于后台一定能完成索引。

源码：worker、处理器、摄取、Embedding、任务领域模型。

权限感知问答

二次校验同时检查租户、条目有效性、当前发布版本、分块快照和实时知识权限。向量库中的旧权限快照不能覆盖主库事实。检索/Embedding 故障时返回保守结果；Chat 故障且已有授权片段时可降级展示依据。

引用保留知识、版本、分块标识；审计保留问题 hash、受限摘要和引用 metadata，不保存完整 prompt 或完整文档。置信度来自检索分数计算，不是模型正确率保证。

源码：检索、回答、审计写入。

AI 出题与人工审核

AI 出题任务当前在创建请求内同步执行；任务实体和“索引后台 worker”是两种实现，不能混为一谈。没有授权上下文时任务失败，不让模型凭空生成。兼容接口 SubmitCandidateForReviewAsync 当前只采纳为草稿，不自动送审。题目停用/修订影响新组卷，已生成试卷使用快照。

源码：生成任务、题库工作流、题目领域规则。

考试与评分

评分支持精确匹配及配置的多选部分得分；它不依赖当前题库答案被后来修改。最后一条返回映射当前存在答案披露和结果可见性问题，见审计第 1 项。过期作答也不等于已实现后台自动交卷，见第 2 项。

源码：考试应用服务、作答领域模型、答题页面。

学习路径

学习路径分配不授予知识访问权，也不替代考试分配。阅读记录绑定具体版本；路径关联版本与当前发布版本变化的行为应查看 TryMapKnowledgeAsync，不要假设版本更新自动继承完成状态。

源码：学习服务、个人 API、个人页面。

知识反馈闭环

图展示常见处理主线，具体关闭条件以领域方法为准。标记 Resolved 前必须关联同一知识下的当前发布版本，且该版本最新索引任务为 Indexed。创建修订会复制来源正文，但不会自动复制附件，也不替代发布和索引。小程序的反馈表单目前没有真实持久化。

源码：反馈服务、反馈领域模型。

知识与 RAG 数据关系

以下 ER 图表达代码中的逻辑关联。连线不等于数据库一定创建了外键，也不展开所有 ABP 审计字段。

KnowledgeItem.CurrentPublishedVersionId 指向当前版本；版本自身还有 IsCurrentPublished。同一知识当前版本的过滤唯一索引是数据库兜底。每次重建会使旧分块失效，保留历史引用所需事实。

向量 payload 是权限和版本的快照，索引成功后仍可能因权限收窄或版本下架变旧。对外返回内容前必须重新读取 PostgreSQL；仅凭 Qdrant 返回不能判断访问授权。

题库、试卷与作答

题目答案和解析会复制进 ExamPaperQuestion，避免后续题库编辑改变历史考试。重要唯一约束包括：计划/用户/作答序号、作答/试卷题目、作答对应成绩。幂等字段用于处理重复保存/提交；并发正确性仍需服务和真实数据库共同验证。

学习路径与进度

阅读记录唯一键包含路径、用户、知识条目和版本；它不是一个全局的“已读知识 ID 列表”。组织任职提供部门、岗位、职级及安全等级，但不同业务的分配维度并不完全相同。

权限由四层共同决定

这是应阅读的检查层次；不同服务的具体代码顺序可能不同。客户端提交的 UserId、TenantId 或筛选条件不能充当授权事实。

规则 服务端依据 关键位置
功能权限 KnowPulsePermissions 和 ABP 授权 Contracts/Permissions、应用服务权限检查
租户隔离 ICurrentTenant、IMultiTenant 与 ABP 数据过滤 多租户已启用；宿主数据 TenantId 为空
知识范围 All、Department、Position、Role、User KnowledgeAccessEvaluator
安全等级 有效任职中的最高等级对比每条规则最低等级 KnowledgeAccessContextProvider
路径分配 全员、部门、岗位、职级 LearningPathAppService.IsAssignedAsync
考试分配和作答归属 计划分配 + 当前用户 + 作答所有者；空分配按全员兼容 ExamAppService.IsAssignedAsync、EnsureAttemptOwner

知识范围是“命中任一启用规则即允许”；安全等级是每条规则的前置条件。历史知识没有启用规则时仍按默认可见兼容；新显式发布策略要求全员一条或定向多条，禁止全员与定向混合。因此迁移旧知识时需识别空范围，不能假设空范围等于禁止访问。

索引 worker 会在查询候选任务时关闭租户过滤，再切换到每项任务的 TenantId 执行。这是后台跨租户调度机制，不能照搬到面向用户的查询接口。

项目接手代码审计

返回导读

这个项目做什么

KnowPulse 为企业提供知识发布、授权问答、题库考试与个人学习。后端和 Web 已有真实业务链路；独立微信小程序目前只演示交互。

本次按“一个 API 实例、一个 Web 实例、同一企业有多名员工同时使用”的负载假设审读，并用知识/路径历史持续增长的情形检查分页。没有假定已具备多实例高可用或做过容量验收。以下问题来自源码路径；未做 HTTP 攻击演示或生产操作。

必须修复

1. 考生响应直接包含标准答案和解析

证据：ExamAppService 的 GetMyPlanListAsync、MapPlanAsync、MapPaperQuestion（约 696、752 行）、MapAttemptAsync（约 787 行）；结果可见性枚举。

  • 这是什么： 管理员和考生共用包含完整试卷快照的 DTO 映射，快照中含正确答案与解析。
  • 问题： 被分配的普通考生查询我的考试或开始作答时，响应的 Paper.Questions[].CorrectAnswers 和 Analysis 就已填入；Plan.Paper 也包含一份。结果映射没有按 Hidden、ScoreOnly、FullReview 裁剪，页面不显示不能阻止客户端读取。
  • 最小修复： 在考生共用映射入口按作答状态与结果策略去除答案、解析和不可见结果，管理预览保留完整内容；两条嵌套 Paper 路径都要处理。补一个未交卷及结果策略的响应内容测试。
  • 不修会怎样： 考试开始前或作答中即可从响应得到答案，“隐藏结果/仅分数”设置也不能实现承诺。

2. 已过期但仍为 InProgress 的作答阻塞下一次尝试

证据：StartAttemptAsync、ExamAttempt.Submit、现有到期测试。

  • 这是什么： 开始考试时优先返回已有 InProgress 作答，目的是断线后继续作答。
  • 问题： 该分支不比较 ExpiresTime。例如计划仍开放、允许两次尝试，用户第一次超时后再次点击开始，仍得到旧的过期记录；保存和提交都会报到期，无法进入第二次。Submit 改为 Expired 后抛异常，也不能依赖这一写入在生产事务中提交。
  • 最小修复： 在开始考试的共享入口先持久化清理过期作答，再选择有效作答并计算剩余次数；补“到期后重新开始”的集成测试。
  • 不修会怎样： 有剩余次数的员工仍可能卡在不可保存、不可提交的旧考试中。现有测试只断言超时保存/提交报错，没有覆盖恢复入口。

3. 公开状态接口可把未执行任务直接标为 Indexed

证据：indexed 控制器入口、MarkIndexedAsync、完整执行 ADR。

  • 这是什么： 保留了直接开始、失败和完成任务的管理接口；正常执行已有共享 Processor。
  • 问题： 有索引管理权限的调用者对 Pending 任务调用 POST /api/knowledge/index-jobs/{id}/indexed，服务只改状态，不验证分块、Embedding 或向量。管理页可显示完成，但检索实际没有新内容。
  • 最小修复： 去掉对外“直接标完成”的入口和远程能力，让完成状态只由真实管道写入；同步调整依赖该接口布置状态的测试。
  • 不修会怎样： “已索引”不能作为运维或用户判断知识可用的事实，排障会被假完成状态误导。

应该修复

4. 不支持的附件会使整份知识反复索引失败

证据：reader 遍历附件、ThrowUnsupportedAttachment、上传引导 的 AttachmentOnly 与发布操作。

  • 这是什么： 上传界面允许图片、音视频等“仅附件”资料；摄取读取版本正文和所有附件。
  • 问题： 例如有效正文所在版本再附一张 PNG，reader 在不支持附件处直接抛异常，正文也无法进入后续阶段。只上传“仅附件”再点击“发布并创建索引”同样进入确定失败和重试。
  • 最小修复： reader 跳过明确不索引的附件，仅在没有任何可读内容时失败；界面明确区分附件发布与可检索内容，补“正文 + PNG”用例。
  • 不修会怎样： 用户合理保存附件就可能打断已有正文索引，失败任务还会消耗重试预算。

5. 列表分页之前加载整租户历史，路径与考试还逐条查询分配

证据：知识快照加载、知识内存分页、学习路径查询、我的考试查询。

  • 这是什么： 列表先加载并计算可见对象，再在内存里 Skip/Take。
  • 问题： 即使只取 10 条，知识管理仍读取全部条目、版本、权限、任务和反馈；每个条目又扫描相关集合。500 条启用路径即会逐条检查分配，再做分页。这是调用次数和读取规模的源码结论，不是已测得的延迟数字。
  • 最小修复： 在数据库下推可见范围、过滤和分页，分配记录按用户/候选 ID 批量查询；汇总统计与当前页明细分开读取，避免每行重扫全表集合。
  • 不修会怎样： 历史越多，首屏消耗越大；多名员工并发打开列表时，数据库请求和应用内存一起增长。

6. RAG 依赖检查与已采纳 MarkItDown 边界冲突

证据：验证脚本、适配实现、项目依赖、ADR 0003。

  • 这是什么： 静态脚本防止预览 SDK 进入核心业务边界；ADR 已允许在 Application 内通过项目接口封装 MarkItDown。
  • 问题： 本次实际执行脚本退出码为 1，命中转换器的 DataIngestion 命名空间和 MarkItDown 包引用。这是仓库规则与实现冲突，不能解释为全部 RAG 测试失败。
  • 最小修复： 仅为已批准的适配文件与准确包名设置窄例外，仍禁止 Contracts/Domain 和其他业务位置引用供应商类型；增加合法适配及非法泄漏的检查样本。
  • 不修会怎样： 开发者按文档运行验证必然失败，难以区分真实边界泄漏和允许的适配实现。
