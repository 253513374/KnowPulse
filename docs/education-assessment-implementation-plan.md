## 2 FR12：规则草稿、确认审核与正式修订

- 使用项目自有共享值类型 QuestionScoringDefinition，包含 SchemaVersion、参考解答、题型适用规则；以受限 JSON 保存在候选、Question 和冻结 PaperQuestion。沿用既有 ABP 应用服务、仓储、UoW，不新建只有一个实现的评分接口或策略框架。
- 填空规则包括稳定空位 ID、顺序、题干对应位置、分值、允许答案和明确的文本、大小写、格式/单位规则；同一答案可对应多个独立空位，不能按去重列表替代。未实现的表达/公式等价必须显式转人工，不能假设错误。
- 主观规则包括稳定评分点 ID、描述、最高分、课程映射 ID，以及可核对的参考解答。每个评分点归一个已确认映射；需要多知识点时拆分评分点，禁止将整分重复归入多个点。
- 每空/评分点分值为正且最多两位小数，总和等于题分；按映射聚合后必须等于 CurriculumPointWeights 分值。多选评分方式也由教师明确确认，课程组卷不得临时重写题目评分口径。D04 的学科规则和参数仍须教研确认。
- 扩展 [QuestionInputs/QuestionDtos](../src/KnowPulse.Application.Contracts/QuestionBank/QuestionInputs.cs) 及候选输出/编辑契约；旧 QuestionAnswer 保留客观题语义，新填空与主观题以结构化规则为唯一依据，不制造占位正确答案。
- 允许保存尚不完整的课程规则草稿；完整校验在 ConfirmCurriculumAsync、SubmitAsync 和审核通过前执行。规则变更纳入内容比较、幂等指纹和创建恢复比较，失效原课程确认及审核。
- [QuestionAppService](../src/KnowPulse.Application/QuestionBank/QuestionAppService.cs) 审核输入增加课程题必需的并发标记及稳定操作 ID；先校验教师看到的版本，再复核教材和来源，重试恢复同一决策，不能批准旧页面未见的新规则。
- 新增不可变 QuestionDefinitionRevision，在审核通过的同一事务冻结题干、选项、答案、规则、课程、实际来源、审核人与 UTC 时间；编辑正式题回草稿，重新确认审核生成新修订，旧修订保留。
- AI 规则仅为建议：缺失、越范围或结构错误保留受控验证结果，教师可修订；生成成功不代替教师确认审核，候选编辑仍检查 ContentRevision。

## 4 FR22/FR23：教学分配下的真实作答与图片

已接通一个有效任教班级的正式测评后端：教师草稿与名单预览 → 明确确认全班或指定学生 → 发布版本及固定名单 → 学生本人详情 → 显式开始或恢复。教师网页入口正在实施。其他任务类型后续实现，不建立尚无行为的类型入口。

- 复用学校、学期、任教、成员、在班关系及 School/Account 并发屏障，复用已冻结 ExamPaper 和评分规则。新增教育任务、不可变发布修订、固定接收人及教育作答事实；现有 ExamAttempt 强制引用 ExamPlan，教育入口不创建组织计划或 All 分配来绕过教学关系。
- 名单预览仅针对本人有效任教班级，返回可识别学生与范围指纹。发布携带稳定操作、已保存草稿版本和所见名单指纹，重新核对关系与当前来源；名单变化要求重新确认。同一事务保存修订及全部接收人；消息投递与发布事实独立。
- 本人任务详情不消耗次数；开始/恢复按当前账号、学生成员与在班关系、固定分配和服务端窗口授权，截止取任务截止与本次时长中较早者，使用半开区间。接收人 CAS 及 `(RecipientId, AttemptNumber)` 唯一约束保护并发开始，冲突后只恢复同一赢家，不重置时间。
- 先接开始/恢复不意味着作答考试已可交付；原始结构化响应、图片、截止封存、人工评分、全量证据及 FR17 统一开放须继续完成。

- 必须接入真实教育任务、班级/学生分配、有效关系和截止规则后开放；历史题卷归属不能单独授予开考或批改权限，不以组织 All 分配替代班级分配。
- 使用教育作答自己的响应修订、每题当前指针和提交事实，不复用绑定 ExamPlan 的 ExamAnswer、自动评分或客户端版本推进。一次操作保存一题完整结构，修订 ID 同时作为稳定保存回执；按空位 ID 保存原文，主观题保留原始文本及有序图片关联，新响应不经过 NormalizeValues。只有真实批量多题保存需要出现时再建立批量操作父事实。
- 服务端拒绝未知/重复空位 ID、跨答卷或跨题图片；部分保存保留未填空位，原始答案和评分结果分开。保存操作稳定幂等、检查服务端版本，旧设备不能覆盖新版本；本机暂存不等于服务端保存。
- 图片复用 BlobStoring 技术，新增独立答卷附件元数据和授权，禁止写入教师个人知识库。验证租户、答卷、题目、所有者及截止；上传与有效答案关联分别确认，支持逐张重试，未关联文件仍属临时附件。
- 参考解答图片属于教师可见用途，题面图片与学生原始作答图片分别授权；冻结引用后不能随源题编辑删除仍被历史使用的文件。格式、数量、容量依 D04 确认。

### 4.1 保存与恢复

本节响应和封存决策见 [ADR 0015](adr/0015-structured-response-revisions-and-single-assessment-submission.md)。当前源码正在集成，实际验证结果另记。

作答根维护全局响应版本，同一事务验证所见版本、追加不可变响应修订、推进本题当前指针及作答版本。不同设备乃至不同题的同时保存可能产生明确冲突；首期从最新服务器版本恢复并显式重试，不默默合并旧答案。相同操作与指纹恢复原保存回执，当前作答查询另行返回最新记录，不把后来答案当作旧操作的结果。

图片按稳定上传操作持久化一个 pending→Uploaded 事实，原始文件内容、hash、归属和 Blob 定位一致。上传完成不等于已进入答案；响应修订独立冻结排序、替换和旋转关联，pending 图片不能提交。未知写入结果保留可恢复定位，不直接删除 Blob 或历史引用原图。

### 4.2 手动交卷与后台截止封存

两个入口调用同一个具体封存用例，在作答 CAS 和每答卷唯一提交约束内固定全部题目的已确认响应修订 manifest，包括未作答项。手动提交核对所见响应/试卷版本，并明确只交已保存内容；超过截止则按实际截止封存，不把迟到本机内容伪装为按时保存。重复或并发入口只恢复实际赢家回执。

ADR 0028 补齐 Web/service 交卷核对：先顺序同步本机题目草稿，或显示漏答、缺空、本机改动与未关联/未确认图片等排除项后明确选择并再次确认。新手动写入须匹配当前答案和上传事实的核对指纹；旧操作回执按原命令恢复，截止封存不要求新确认。本机草稿不随仅交已保存部分自动删除。服务和链接客户端状态已验证，真实登录页面、微信及生产并发验收仍待完成。

截止 worker 按记录的租户、发布版本、固定名单和作答事实处理，不依赖学生登录、教师当前教材或已结束成员关系，否则离线和转班会使答卷永远不能封存。学生截止后的只读恢复仍核对本人及当前教学关系；后台封存不授予读取权。人工批改和任务最终开放按下节的独立用例实施。

## 5 FR16/FR17：全量逐题评分与开放

- 新增逐题评分记录：绑定答卷、冻结题目、答案版本/hash、规则版本，保存逐空/点评分、评分人、UTC 时间、并发标记和操作标识。正确题、未作答题也保存证据，不能只有错题。
- 评分草稿可编辑，确认后不可变；改分创建后续修订保留旧记录。确认检查原答案版本、点分边界、总和及当前任教/批改授权，同操作重试恢复原结果；复用现有服务和事务。
- 使用具体领域函数按冻结规则计算，人工未确认分表示待处理，不能计零。提交状态保持 Submitted，评分是否完整由全部题目确认事实计算，界面显示待批改数量和已确认数量，不新增重复状态字段。
- 最终开放须按 FR17 固定有效提交集合、截止封存、全任务完整批改及教师确认；单份答卷批完或考试窗口结束均不能单独开放临时学生总分、答案或评分要点。

### 5.1 冻结评分内核

两个具体领域函数已按 [ADR 0016](adr/0016-frozen-question-scoring-and-conserving-curriculum-evidence.md) 落盘并通过领域专项，不建立评分接口或策略框架：从冻结 `ExamPaperQuestion` 与原始响应计算逐空/点评分，再从已完整确认的结果和冻结课程映射构建知识点评分证据。客观题也输出评分事实；任何人工空位或主观评分点未确认时，题目总分保持 NULL，不用零分占位。持久化评分、后台初始化与教师统一发布已按 5.2 接入。

学生选择仍使用实际冻结选项的稳定 key，原始响应不清洗。既有审核允许正确答案与选项 key 大小写不同，判断答案允许 `true/false` 与“对/错”；评分仅将冻结答案依据唯一解析到其实际选项或判断值，不能把合法已批准答案误判为错误。选项身份歧义、未知稳定身份和坏规则拒绝处理。填空仅执行明确的 Exact、IgnoreCase 和 TrimWhitespace；Manual 不推断公式等价。

空位与主观评分点按冻结映射聚合。客观题采用确认的知识点权重与各点满分，把实得分转为整数分，以固定最大余数及稳定映射 ID 顺序、有界多轮分配，只向未封顶点补分；满分直接采用确认的满分分配。所有知识点实得分与满分分别严格等于题目实得分与满分，算法版本进入后续证据事实。两个内核的测试不等同于评分已自动运行或学生成绩已开放。

### 5.2 持久化事实与任务统一开放

以下持久化和应用用例已按 [ADR 0017](adr/0017-confirmed-question-grades-and-task-wide-result-release.md) 实施，教师批改/统一发布与学生网页结果已接接口。实际构建、自动化及 PostgreSQL 证据见[实施记录](education-implementation-progress.md)；登录后页面、真实微信、真实学科样本及负载验收分别管理。

| 事实 | 必须保留的行为 |
| --- | --- |
| 每题评分根与不可变评分修订 | 唯一提交和冻结题目配对；修订操作 ID、请求指纹、原响应修订引用/hash、规则及算法版本、逐点分、全量映射证据、反馈、评分人和时间；草稿与已确认指针分开，改分保留旧确认及必需原因 |
| 任务封存事实 | 自然截止后固定发布修订的最多 3000 个接收人及各自确切作答/唯一提交或未参与终态，受限 manifest 不因动态名单变化而改变；尚有进行中作答不得建立完整封存 |
| 正式结果发布及每答卷发布项 | 教师确认全部有效提交评分完整后，冻结本次所有逐题确认修订和总分；每答卷有受限修订清单，避免任务级所有题巨大 JSON；成绩和讲评时间独立，旧发布版本保留 |
| 成绩复核申请 | 学生仅对本人已开放结果申请，稳定操作回执与处理原因保留；处理期间原正式分仍可读，纠正后关联新评分及发布修订 |

上述表中评分根、评分修订、任务封存、结果发布、逐答卷发布项及复核申请共六类事实。评分修订同时保留确认回执与逐题证据，不另外建立相同内容的回执或证据表；正确题、错误题和未作答题均纳入。封存 manifest 仅放身份及提交引用，不放全部原始答案。

教师写入统一使用 School→教师账号→Task→评分根屏障。按冻结任教关系与当前有效教学身份授权，不把教师当前选用的新教材或后来来源撤回误当作原答卷评分权限。封存与开始在相同任务屏障下重查服务端 UTC；只有完整封存且不能追加尝试后，才按所见评分集合版本统一发布。评分草稿不改变学生原正式分；发布后的改分确认在同事务生成并切换新的正式发布快照，派生报告保留过时状态直至重算完成。

必要教师用例包括批改概览、精确提交/原图、评分草稿、确认及原操作恢复、封存预览/确认、最终发布及发布回执恢复；学生用例包括本人结果与复核申请。所有学生嵌套返回共同执行 Hidden/ScoreOnly/FullReview，完整讲评才开放逐题答案、解析和反馈，始终不返回教师私有题源、草稿或他人记录。D07 的提前结束、加时、补考和作废计分规则另行确定，先完整实现自然截止默认流程。

## 6 实施路径、迁移与验收

- 首个实现切片完成 FR12 规则草稿→完整校验/显式确认审核→正式不可变修订→FR13 冻结及安全预览；再在真实教学分配基础上完成 FR22/FR23 作答图片与 FR16/FR17 批改开放，不将前一切片称为完整教学闭环。
- 页面路径：[QuestionEditor](../src/KnowPulse.Blazor.Client/Pages/QuestionBank/QuestionEditor.razor) 编辑逐空/点评分；QuestionReview 展示审核依据；AiCandidates 保存建议和编辑；QuestionWorklist 补题型/规则状态；Education/Papers 扩展冻结预览；随后改 Take 并新增教育批改页。企业 Management 不自动开放新教育题型。
- FR12 迁移增加候选/Question/PaperQuestion 规则列、正式修订表与快照修订引用；FR16/FR22–23 随接入增加答案格式、答卷附件及逐题评分记录。旧行保持 null/legacy，不补造确认或修订事实；新分值沿用 (18,2)，同步 EF 映射并独立验证 PostgreSQL 升级及配对约束。
