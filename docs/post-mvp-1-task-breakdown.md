## 1. 拆分目标和边界

### 1.1 拆分目标

MVP-1 已完成权限化 RAG 问答闭环。后续任务一次性拆到可派发、可排期、可验收的粒度，覆盖：

- MVP-1 收尾固化：验收证据、演示数据、回归门禁和基线文档。
- MVP-2：题库、AI 出题、审核、组卷、在线考试、评分、成绩和错题闭环。
- MVP-3：学习路径、阅读记录、知识反馈、题目质量和运营报表。
- MVP-4：生产化运维、安全加固、观测、备份恢复、性能压测和部署发布。
- 后置增强：主观题 AI 初评、复杂防作弊、企业集成、OCR/视频知识解析、服务拆分和消息队列。

### 1.2 执行原则

- PostgreSQL 仍是业务事实库，Qdrant 只作为可重建索引库。
- AI 生成题目、摘要、标签、评分建议不得直接进入正式业务状态，必须经过审核或复核。
- 已开始考试的试卷必须使用快照，不能被后续题库修改影响。
- 考试答题页不能把倒计时、答题草稿或提交状态只保存在 Blazor circuit 内存中。
- Agent workflow 只在多步骤编排、人审节点、工具调用审批确有价值时启用，不作为普通 CRUD 或规则评分的默认实现。
- RabbitMQ、微服务、复杂防作弊、大规模 OCR 和完整 BI 不进入 MVP-2 主线，除非出现明确容量或合规触发条件。

### 1.3 任务粒度约束

- 单个任务建议控制在 0.5 到 3 人日。
- P0 任务必须进入对应阶段完成判定。
- P1 任务默认进入该阶段交付范围，但可以在不破坏闭环时延后。
- P2 任务属于增强或运营效率，不阻塞主链路上线。

## 4. MVP-2：题库、AI 出题与考试闭环

### 4.1 MVP-2 交付边界

必须交付：

1. 题库 CRUD、题型、选项、标准答案、解析、难度、知识点和来源引用。
2. AI 基于 RAG 生成候选题，候选题进入待审核，不能直接成为正式题。
3. 题目审核通过、驳回、退回修改和审核记录。
4. 相似题检测，避免 AI 或人工重复造题。
5. 按岗位、知识点、题型、难度和数量组卷。
6. 考试计划、考试分配、试卷快照、在线答题、自动保存和提交。
7. 客观题自动评分、成绩、错题记录和考试结果查询。

暂缓：

- 主观题 AI 自动评分正式入成绩。
- 复杂防作弊。
- 完整 BI。
- 微服务拆分。
- RabbitMQ。
- Agent 自主规划和跨 Agent 协作。

### 4.3 Backend 任务详情

#### KP-MVP2-BE-001 实现题库领域模型与迁移

- 阶段：MVP-2
- 模块：QuestionBank
- 类型：Backend
- 负责人角色：Backend
- 优先级：P0
- 预估：2.5 人日
- 依赖：S0

任务说明：

实现题库聚合根和持久化模型，覆盖题干、题型、选项、标准答案、解析、难度、状态、知识点、来源和审核状态。

建议实体：

- `Question`
- `QuestionOption`
- `QuestionAnswer`
- `QuestionAnalysis`
- `QuestionKnowledgePoint`
- `QuestionSource`
- `QuestionReview`
- `QuestionSimilarityCheck`

验收标准：

- 支持单选、多选、判断和填空的最小题型。
- 题目状态至少包含草稿、待审核、审核通过、驳回、停用和归档。
- 题目可绑定知识条目、知识版本、chunk 或人工来源说明。
- 选项题至少有一个正确答案，多选题允许多个正确答案。
- 题目难度、适用岗位、安全等级和标签可持久化。

完成定义：

- EF Core 迁移完成。
- 领域测试覆盖题型约束、答案约束和状态流转。
- 不把 AI 输出原始大文本直接作为唯一业务事实。

#### KP-MVP2-BE-003 实现题目审核流和正式入库规则

- 阶段：MVP-2
- 模块：QuestionBank
- 类型：Backend
- 负责人角色：Backend
- 优先级：P0
- 预估：2 人日
- 依赖：KP-MVP2-BE-001

任务说明：

实现题目提交审核、审核通过、驳回、退回修改和审核记录。AI 生成题必须先进入待审核，不允许直接被组卷使用。

验收标准：

- 未审核通过题目不能进入正式题库筛选和组卷。
- 审核记录包含审核人、审核时间、审核意见和前后状态。
- 被驳回题目不能被考试引用。
- 题目修改后需要根据规则重新进入草稿或待审核。

完成定义：

- 审核流领域测试和应用服务测试通过。
- 审计日志能追踪审核动作。

#### KP-MVP2-BE-004 实现题目知识点、来源引用和版本快照

- 阶段：MVP-2
- 模块：QuestionBank
- 类型：Backend
- 负责人角色：Backend
- 优先级：P0
- 预估：2 人日
- 依赖：KP-MVP2-BE-001, MVP-1 RAG

任务说明：

题目必须能追溯到知识来源。AI 题保存生成时使用的知识版本、chunk、引用摘录和 prompt 版本；人工题可保存人工来源说明。

验收标准：

- AI 生成题至少保存一个可追溯来源，除非明确标记为无引用的人工题。
- 来源引用保存受控长度摘录和 hash，不保存完整知识正文。
- 知识版本后续修改不影响历史题目来源解释。
- 试卷快照能复制题目关键字段，避免历史考试被题库变更影响。

完成定义：

- 来源引用测试覆盖知识版本变更后的历史解释。

- 阅读记录和学习进度按用户、知识版本和学习路径保存。
- 知识新版本发布后能标记需要复学或保留已完成状态，规则必须明确。
- 管理员可查询部门/岗位维度的学习完成率。

#### KP-MVP3-BE-003 实现知识反馈和纠错流程

任务说明：

用户可以对知识内容提交问题、过期、错误、缺失和建议，内容管理员可以处理并关联到知识版本修改。

验收标准：

- 反馈包含类型、说明、来源知识、提交人和处理状态。
- 处理记录包含处理人、处理意见和关联的新知识版本。
- 反馈不会直接修改已发布知识。

#### KP-MVP3-BE-004 实现题目质量反馈和错题聚合

任务说明：

基于考试错题、人工反馈和审核记录聚合题目质量问题，帮助管理员发现歧义题、过难题和错误题。

验收标准：

- 题目可看到答错率、被反馈次数、最近考试使用次数。
- 高错题率或高反馈题进入待复核列表。
- 停用问题题目不影响历史考试成绩解释。

#### KP-MVP3-AI-001 建立 RAG 评测集和评测运行记录

任务说明：

建立覆盖常见制度问答、岗位流程、无答案问题、权限边界问题的 RAG 评测集，并保存评测运行结果。

验收标准：

- 评测集包含问题、期望引用、期望拒答、适用权限上下文。
- 评测运行记录保存命中率、引用准确率、无答案拒答率和越权召回率。
- 越权召回率必须作为硬失败指标。

#### KP-MVP3-BE-005 实现运营报表聚合任务

任务说明：

聚合知识阅读、考试通过率、错题率、题目质量、RAG 无依据问题和 AI 出题审核通过率。

验收标准：

- 报表查询不直接扫大表，至少有聚合任务或合理索引。
- 支持按时间、部门、岗位和考试筛选。
- 报表数据能追溯到原始业务记录。

### 6.2 关键任务说明

#### KP-MVP4-DEVOPS-001 建立私有化部署配置基线

任务说明：

把本地 Docker Compose 开发环境整理成可交付的私有化部署基线，区分开发、演示和生产配置。

验收标准：

- 不使用 `latest` 镜像 tag。
- 真实密钥只通过环境变量或 secret 注入。
- PostgreSQL、MinIO、Qdrant、LiteLLM、ABP Host 和 Blazor 的地址、证书和端口可配置。
- 文档说明最小硬件、端口、数据卷和升级路径。

#### KP-MVP4-DEVOPS-002 建立备份、恢复和重建演练

任务说明：

建立 PostgreSQL、MinIO、Qdrant 的备份恢复流程，并验证 Qdrant 可由 PostgreSQL 和 MinIO 重建。

验收标准：

- PostgreSQL 备份可恢复到新库。
- MinIO 文件可恢复并通过应用服务下载。
- Qdrant collection 可清空后通过重建索引恢复。
- 演练记录包含耗时、命令和失败处理。

#### KP-MVP4-OBS-001 接入 OpenTelemetry 和关键指标

任务说明：

为 API、索引任务、RAG、AI 出题、考试提交和评分建立观测指标。

验收标准：

- 指标覆盖 API 延迟、错误率、Qdrant 检索延迟、embedding 耗时、LiteLLM 模型调用耗时、Hangfire/后台任务积压、考试提交成功率。
- 日志带租户、用户、业务 ID 和 correlation ID，但不带敏感正文。
- 可以定位一次 RAG 回答或考试提交的端到端链路。

#### KP-MVP4-SEC-001 执行权限、租户和敏感日志安全加固

任务说明：

系统性复核知识、RAG、题库、考试、成绩和报表权限，避免菜单权限和应用服务权限不一致。

验收标准：

- 未登录、普通用户、考试用户、题库管理员、考试管理员、系统管理员权限边界可测试。
- 跨租户数据不可读写。
- 审计和模型调用日志不保存完整知识正文、完整附件、完整 prompt、标准答案泄漏到非授权角色。

#### KP-MVP4-PERF-001 建立 RAG 和考试压测脚本

任务说明：

建立核心压力脚本，覆盖知识检索、问答、考试开始、答题保存、提交和评分。

验收标准：

- 给出基准并发、响应时间和错误率。
- 识别数据库慢查询、Qdrant filter 慢查询和考试保存热点。
- 压测数据可清理或使用独立前缀。

#### KP-MVP4-REL-001 建立发布、回滚和迁移检查清单

任务说明：

建立每次发布前后的检查清单，覆盖迁移、备份、配置、健康检查、回滚和验收。

验收标准：

- 发布前必须完成数据库备份和迁移预检查。
- 发布后必须执行健康检查、核心登录、知识/RAG、题库/考试冒烟。
- 回滚路径明确，包括应用版本、数据库迁移和 Qdrant collection 的处理。

## 8. 推荐执行顺序

1. 先完成 S0，避免在 MVP-2 开发中丢失 MVP-1 的安全回归基线。
2. MVP-2 第一条主线：题库模型、题库 API、审核流、题库页面。
3. MVP-2 第二条主线：AI 出题 prompt、任务管道、结构化校验、相似题检测、候选题审核页面。
4. MVP-2 第三条主线：考试模型、组卷快照、考试分配、答题保存、提交评分、考试页面。
5. MVP-2 收尾：权限审计、自动化测试、演示数据、答题页浏览器验收。
6. MVP-3 先做学习路径和阅读记录，再做反馈纠错、质量报表和评测集。
7. MVP-4 在准备试点或私有化交付前启动，不要等到上线当天补部署和备份。

## 9. MVP-2 完成判定

MVP-2 必须同时满足：

- 人工题和 AI 候选题都能进入统一审核流。
- AI 生成题未审核通过前不能进入正式题库和考试。
- 题目来源、知识版本、chunk citation 和审核记录可追溯。
- 相似题检测能提示重复风险。
- 管理员可以按岗位、知识点、题型、难度和数量组卷。
- 已开始考试的试卷使用快照，后续题库修改不影响历史作答和成绩。
- 考生可以开始考试、自动保存答案、提交试卷。
- 客观题评分可重复执行且结果一致。
- 成绩和错题记录能追溯到原始答题和试卷快照。
- 题库、AI 出题、考试、成绩均有权限点和审计记录。
