# ADR 0045: Version plan execution control and private teacher decisions

Status: Accepted, 2026-10-18. Extends ADRs 0023, 0025 and 0026; formal assessment rules and D03 remain unchanged.

Inbox follow-up: [ADR 0050](0050-public-plan-and-difficulty-handling-inbox-notices.md) adds generic in-app notices for actual public execution changes. Private Continue decisions and reasons remain private; notification reads do not create execution or learning evidence.

Reminder follow-up: [ADR 0047](0047-confirmed-assessment-reminders-and-private-student-inbox.md) adds explicit in-app reminders for formal assessments and checks current plan publication/execution before a new reminder. Other activity reminder senders remain deferred; the original sender statement below describes this ADR's initial slice.

## Decision

FR33 needs pausing/resuming and the teacher's continue/adjust/end decision without rewriting a published plan or pretending a student has achieved its goal. Add a separate immutable decision sequence to each plan, independent of its content revision sequence. Every event fixes the owner, student, exact publication, predecessor, prior/resulting execution states, controlled evidence, private reason, request fingerprint and recorded time. The root maintains a private decision head/count plus execution state and its last change time.

Running means new execution is enabled subject to all existing gates; it does not mean activities have started. Pause changes Running to Paused. Resume requires Paused, current personal basis, authorized materials and a still-valid period. Continue records a reviewed decision while Running. Adjust pauses new execution and requires a separately saved/confirmed/published replacement before Resume. Publishing that replacement preserves Paused rather than silently resuming. End and Terminate are terminal for new execution and republishing this root; a subsequent cycle uses a new plan. None of these actions deletes a publication, completion, submission, score or exposure.

Four teacher operations provide a current review, explicit decision, exact operation recovery and head-fixed paged history. Both TeachingPlanManage and AnalysisManage, active account/tenant, ownership and the current exact teaching/student relationships are mandatory. A stable operation ID recovers its original receipt before testing stale expectations; different input cannot reuse it. Expected publication, private control head, root stamp and a freshly recaptured evidence fingerprint prevent an intervening content, student event, follow-up, material, binding, seal or confirmed-grade change from silently becoming the reviewed state. Mutations and pointer advancement share the existing relational school/account barriers and transaction.

## Evidence and privacy

The review combines the immutable publication/baseline with actual activity event identifiers, current student action, follow-up identifier, material availability, exact formal task/recipient/attempt, seal time and current confirmed grade revision identifiers/hash. It does not copy answers, private notes, feedback or marks into the decision evidence. Assessment metadata and grading versions additionally require AssessmentManage; missing permission remains explicit unknown evidence. Up to 50 activities, 500 grade references per activity and 2 MiB of controlled evidence are allowed. The teacher can open the existing activity, report and grading views to inspect the underlying evidence; these counts are not a mastery or intervention-effect calculation.

Continue, Adjust and End require the teacher to acknowledge reviewed evidence and uncertainty. Missing or incomparable evidence is not a measured weakness, zero mark or automatic achievement. Reasons/reflection are owner-private, audit-excluded business facts; recording a reflection does not submit it to a school library or an AI provider. Public student DTOs add only execution state/time and separate start/material capabilities. A private Continue event does not change the student's execution-change time or expose private decision identifiers/counters/reasons.

Stale source does not prevent a currently authorized teacher from stopping execution; it does prevent Resume/Continue. Source authorization failure becomes a controlled non-current signal, not disclosure of the old source. Withdrawal retains authorized teacher history and its last publication as a read-only review; it cannot be resumed through that historical view. Current ownership and relationships still govern history, so this is not a D06 historical-access or administrator bypass.

## Execution consumers

Student plan bodies retain the existing current-source, FullReview, relationship and material gates. Paused/ended/terminated plans can retain an otherwise authorized body and the student's own already-provided history; status is independent from content availability. New activity starts are rejected server-side, including completed-activity restarts. An already started non-formal activity may complete or report difficulty under the existing rules. Material reading after stopping requires a previous actual activity start or formal attempt as well as every original D03/material permission check. Merely receiving a plan is not an activity start.

The shared formal assessment start guard checks execution state, so the original assessment URL cannot bypass a paused plan. Already started attempts retain their original timer, save/submit/deadline and result rules; pausing does not cancel or extend a real exam. Formal progress distinguishes stopped new starts from an existing attempt's recovery. Both workload services exclude unexecuted stopped arrangements; an existing formal attempt is still scheduled under its actual assessment deadline. Other independent tasks remain. No reminder sender currently exists for these plan activities; future plan reminders must apply this same execution gate rather than recreate a task.

Web provides `/education/teaching-plans/{id}/execution`, linked from the editor and activity progress, with guarded private input and account/tenant/plan-scoped exact pending commands. An unconfirmed response is recovered or resent explicitly; receipt recovery reloads the current state rather than rolling it back. Student Web/native show status and disable new starts/material reads using server capabilities; native storage does not persist plan bodies or teacher decisions. Formal changes remain Web actions under FR33's first-release division of work.

## Persistence and acceptance limits

Migration `20261018085601_AddEducationTeachingPlanExecution` adds four root columns and a decision table, four paired Restrict keys including the current head, plan sequence uniqueness and state/predecessor/evidence constraints. Legacy roots default to enabled execution; existing publication/authority/timing gates still apply. It backfills no activity, completion, decision, grade or exposure.

Domain, explicit HTTP contract and SQLite service tests cover transitions, terminal/republication rules, exact old recovery, changed student/grade evidence, withdrawn read-only history, private/public projections and started versus unstarted formal execution. Real isolated PostgreSQL/HTTPS and signed native Page flows verified continue/adjust/end across three publications, preservation of a naturally expired original attempt, a separately confirmed next cycle, actual paused save/submit, corrected-grade references and current-access failure. Eight PostgreSQL invalid writes were rejected and rolled back. Browser evidence covers normal OIDC login, the ended review, nine history rows, grading links and disabled terminal form; it is not the complete browser write/weak-network workflow. The later withdrawn read-only fallback is verified through service tests, not a repeated browser run.

Full regression counts, same-data failures/continuations, hashes and cleanup are recorded in the implementation progress and `TestResults/education-plan-execution-verification-summary.json`. Real teaching quality/calibration, true WeChat/SDK/devices, complete browser/weak-network and production concurrency/capacity, D06/D07/D09/D10 and remaining education features continue as separate requirements; this slice does not complete the full PRD.
