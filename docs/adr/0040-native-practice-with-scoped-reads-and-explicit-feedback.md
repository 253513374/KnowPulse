# Native practice keeps school scope, private drafts and explicit feedback separate

Date: 2026-10-18. Status: accepted for implementation. Extends ADR 0036 and the native part of FR27, without changing D02, D03 or D06.

Native students use the existing education practice service and frozen scoring rules. A school-filtered metadata hub and a single-round page support the five response types, original image selection, exact preparation, explicit sharing and one sealed teaching copy. Starting a round or uploading does not share a draft. Practice reference marks, including null manual marks, remain separate from the original answer, official score and independent mastery evidence. This does not add teacher practice grading or a new teacher-feedback revision workflow.

The original start/submit DTOs and fingerprints stay unchanged so old operation receipts survive this addition. Separate school-checked start/detail entrypoints validate selected school before creating a round or providing a question/feedback. Optional SchoolId filters the existing list before count and pagination; omitted school preserves the old Web query. Metadata list/detail projections include their actual school. A new start-receipt lookup first checks the student's recorded school relation, then returns null for an absent operation or the exact existing receipt. It does not reinterpret a generic authorization denial as proof that a start failed.

After a lost submission response, a cold native page initially reads the pending metadata and offers receipt recovery. It does not automatically request answer-bearing detail. Explicit detail navigation/read may provide feedback only under the original current full-review and confirmed-grade gates. A successful submit/recovered receipt likewise does not automatically read feedback. Source closure stops new execution and withholds the question/criteria/evaluation while preserving the student's authorized submitted copy and original images. A new release never silently rebinds a previous round.

Native drafts require explicit local-storage consent. Stored content contains only the student's own response, image references and exact pending command, never the source question/answer/criteria. Scope includes API/application/client, tenant/account, school and round; start-operation metadata has its own recipient/question scope and is discoverable from the school hub. Logical 24-hour expiry is checked on use. Unknown commands cannot be replaced by a fresh operation: query first, then explicitly retry the same ID/content. Expired/cleared submit bodies cannot be reconstructed; receipt lookup remains. Closing tracking never undoes a server fact.

Original images reuse the existing SHA-256/header/size validation and immutable application-owned local copy. Retrying/reselecting requires the same bytes and metadata; confirmation enters only the private selected references until explicit submission. Rotation/order/removal change references and do not rewrite/delete original bytes. An authenticated GET adapter delegates to existing student image authorization with both permissions, no audit body and private/no-store. Teachers continue to see only selected submitted images. Hidden views and late downloads cannot restore former content; logout/identity/permission loss attempt private-body/file cleanup and report unconfirmed cleanup. Logical expiry and best-effort deletion do not promise physical shared-device erasure.

No migration, new permission, provider, worker or dependency is needed. Existing Web practice/teacher review and legacy HTTP routes remain available. Real WeChat/SDK/WXML/device, full browser/weak-network, school exit/retention and production capacity acceptance remain separate from local Page-script, HTTP, database and Blob verification.
