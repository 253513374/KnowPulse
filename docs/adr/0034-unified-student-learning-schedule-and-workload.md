# Unified student learning schedule and workload

Date: 2026-10-18. Status: accepted for the manual Web/service slice. Extends ADRs 0025, 0026, 0031 and 0033; does not replace the original plan-only workload contract or settle school calendar, retention or exit policy.

The student needs one current schedule across plan activities, independent material tasks, corrections and formal assessments. The new caller-derived `GetMyLearningWorkloadAsync` requires LearningParticipate and a current active account. Plan data additionally requires TeachingPlanView and retains the existing AssessmentParticipate requirement when its available body depends on assessment evidence; corrections and assessments require AssessmentParticipate. Missing feature kinds are explicitly reported as omitted, with no source counts disclosed for those permissions. The primary permission/account are checked again before returning; a removed optional permission removes its items. No client-supplied student or school identity grants access.

Candidate queries filter the exact caller/tenant, current publication and effective student membership/enrollment/class/term before applying the 1,000-candidate-per-kind quota. Per-source services/guards then recheck recorded authority and current source facts. Internal study/correction metadata readers are explicitly RemoteService(false), and reuse their actual student authorization and availability rules. No lookup supplies task bodies, materials, answers, teacher notes or feedback text to the workload response. Workload does not open plans, create missing activities, record first provision/exposure, start/resume/seal attempts, create student progress, submit work or change grades/mastery.

The projection contains source kind, the source item/reference and publication IDs needed for navigation, subject/class labels, start/deadline, estimate and state. A plan item ID is its frozen step ID, not evidence that an activity has been created or provided. Source content, grade/release identifiers, private-library identifiers, names of other students and teacher-private explanations are absent. Results are private/no-store and excluded from body auditing. Navigation opens the actual task and rechecks its current gates. Study/correction links target the fixed recipient/delivery; plan links retain their exact public version.

## Estimate rules

- A half-open UTC deadline window is limited to 31 days, retaining the existing plan-workload calendar convention. Dates are not silently converted to school-local days. The UI clears the previous result when the window changes.
- Ready and Scheduled items contribute known planned minutes. This is the original estimate for unfinished work, not measured remaining effort or a mastery signal. Blocked and Overdue items remain discoverable but do not contribute to that total. A zero known total does not prove there is no unresolved work.
- Current completed material/plan actions are excluded. A later difficulty reappears as blocked; private teacher handling does not complete it. Replacement uses only the new current publication and does not inherit the old completion. Withdrawn versions are omitted from current scheduling and retain their separate histories.
- A correction with no submitted copy is pending; a submitted copy awaiting review is excluded. NeedsRevision for that exact current copy restores the original estimate; Accepted excludes it. An earlier copy's review never applies to a later copy. The list may expose this small work-state enum only under the current original full-review/confirmed-grade gate, without review text. If that gate closes or changes, work state is unknown and the current correction is shown blocked, with no known minutes or hidden review decision.
- A real bound formal assessment whose fixed recipient can still be located is counted in the assessment section using the actual fixed recipient, assessment deadline/duration and, once started, individual expiry. The corresponding plan step is not added again. An unbound diagnostic/reassessment step is blocked. A started assessment continues to follow its own rules after binding stops; a real sealed submission, rather than an activity claim, removes its student work. An ongoing attempt's estimate is capped by its remaining server time limit, without claiming measured attention. Workload never seals an expired attempt.
- An unavailable plan may have its whole body withheld. It contributes only a current unestimated-plan count, independent of the requested calendar window. Neither its hidden dates nor its step count/minutes are used to filter that count. This prevents repeated date queries from revealing a withheld schedule. The UI explains that these plans cannot be checked against the chosen window.

There is no deduplication by title, original question or matching material: separately published assignments remain separate facts. The only formal deduplication above follows the real activity binding. Source checks happen one at a time and do not form an atomic cross-school snapshot. At most 3,000 result items are returned; exceeding a workload quota fails the whole calculation with no partial total. School retention/archival and realistic load policy remain separate.

This is a computed read model with no database schema change or migration. The old nine-operation activity interface and its plan-only workload semantics remain available for existing readers, including those lacking LearningParticipate. The new Web page `/education/workload` is linked from the material, correction, plan activity and result pages. Real authenticated browser/device/WeChat flows, full PostgreSQL application concurrency and production capacity remain unverified by SQLite/service or compilation evidence alone.

## Native school-scoped workload extension (2026-10-18)

GetMyLearningWorkloadAsync now accepts an optional schoolId. Effective membership and enrollment subqueries apply it before every kind-specific candidate quota, including withheld-plan counts. The response echoes the selected nullable SchoolId; choosing a school grants no authority. Omitting it preserves the existing all-accessible-school Web query and generated GET path; the separate plan-only contract and its input DTO remain unchanged. This is a computed projection with no migration.

The native student workspace verifies the selected school and real UTC half-open dates, then uses the same four-kind service. It checks the returned school/window, supported enums and daily totals before showing the estimate. Omitted plan permissions cannot carry hidden plan counts. Daily drilldown stays in memory; only 20 task cards enter the view at once. Refresh, date changes, hide and identity changes clear the old result. No workload response or source body is persisted by this page, and it creates no provision, activity, attempt, submission or mastery evidence.

Study and assessment cards link to their existing native recipient pages. Plan and correction execution currently use explicit copy-to-Web links, preserving exact plan publication or correction delivery IDs. Session.portalUrl allows only those precise paths on the configured portal origin, without credentials; normal Web login and source authorization remain necessary. This intermediate handoff does not complete native plan/correction execution. UTC days, optional-feature omissions, blocked/overdue exclusions and date-independent unknown-plan warnings retain the original ADR semantics; actual WeChat/SDK/device/browser acceptance remains separate.

The subsequent 2026-10-18 plan slice replaces only the plan handoff with a native exact-school/publication/step link (ADR 0025 extension). Corrections retain the explicit Web handoff. Workload reads and navigation still do not themselves provide a plan body, start an activity or begin a formal exam.

The subsequent correction slice (ADR 0033 extension) replaces that remaining correction handoff with its native exact-school/delivery link. All four supported workload kinds now use native detail pages; the unused clipboard branch and native/Web flag are removed. Explicit Web backup links remain on the relevant detail pages. Navigation still does not submit work, begin exams or expand source authority.
