# ADR 0052: Teacher relation correction requests and atomic school resolution

Status: Accepted, 2026-10-18. Implements the teacher review/request part of FR02/FR35 under ADRs 0008 and 0051. It does not decide account recovery, school shutdown, transfer of teaching work or broader D06 historical access.

## Teacher request, school authority

A current active account with an effective Teacher membership in the selected school can page through its own teaching relation metadata and submit a correction explanation. Select an exact own original relation or explicitly report a missing relation; shared text requires confirmation. The request fixes account, school, original membership and optional original assignment/stamp/end. It contains no client-selected target teacher. A general platform role, student membership or request submission cannot grant teaching/student-data access.

Only the requester under that original current Teacher membership may read or withdraw its pending request. My-list filters current tenant, school, account and original effective member before count/paging, with final scope checks. Original/current relation summaries contain class/subject/term labels and dates, not students, answers, scores or private knowledge. Current school managers with SchoolManage can review school-shared requests and explicitly choose no change, end, add missing or replace. The teacher can read their resolution text; it is not a private observation. Default personal knowledge, notebooks, RAG and export ownership are unchanged.

## Source validation and one transaction

Processing checks request concurrency and the exact school configuration revision reviewed. Ending/replacing also requires the original assignment still match both its request-time and reviewed stamp. An externally changed original must be explained without changes or resubmitted; the UI does not offer rewriting an already ended relation. There is no correction that changes the teacher on an existing relation, backdates a new grant or extends ended history.

Resolve an add/replace against the requester's fixed account and original active Teacher membership. Reuse the original school assignment preparation rules for same-tenant references, term/class, membership coverage, period and overlap. Validate the entire replacement before ending the original. In the existing School/account transaction, save the original end, new or exact-existing relation and immutable terminal request fact together. A future cutover uses the same old end/new start; an earlier requested time is clamped to the processing decision time. Preserve original relation identifiers and their request-time end, actor, reason and operation chain. Do not transfer task/feedback/report ownership, personal assets, grades or learning evidence. Ending changes subsequent scope; managers must check unfinished teaching work before confirming.

Extract assignment preparation from the original AssignTeacher method without changing its public contract or validation/duplicate behavior. Source barriers/fingerprint/paging helpers already used by invitations receive shared school names and are reused; no new permission bypass, dependency or generalized workflow framework is added. Source states and teacher-facing result capabilities remain separate from current effective workspace scope.

## Operations, clients and persistence

Eight operations extend IEducationSchoolAppService: own relation list, own request list/detail/submit/withdraw, and manager list/detail/resolve. All check active identity and the relevant school facts; manager calls explicitly check SchoolManage. Existing conventional proxy registration and private/no-store result filtering apply. Contract checks verify the actual eight current ABP routes. The server never takes TeacherUserId from a submit or resolve DTO.

Web uses a scoped request page, with the manager entry in school management and the teacher entry in each real school workspace. Native adds a simple teacher request/read/withdraw page in the same AppID. School name/code, source choice and sharing confirmation are explicit. Default picker selection is a valid placeholder, not an implicit missing-relation request. Source/account/request-generation guards discard late results. Browser navigation and native in-page reads check unsent text; native background/hide clears memory with visible disclosure and an available SDK leave alert. No text or original command payload is persisted locally; only environment/account/school/action/operation identifiers are stored. Exact receipts recover uncertain operations; a receipt never restores a subsequently ended relation or substitutes another terminal action. No automatic resend occurs.
