# Keep reusable phrases owner-private and explicitly copy selected teaching text

Date: 2026-10-18. Status: accepted for implementation. Verification is recorded in the education implementation progress document.

FR19 requires personal reusable phrases and teacher observations on mobile. ADR 0018 already makes observations immutable and separate from student feedback. Its existing Web observation operations and request fingerprints remain compatible. New school-scoped create/list and exact-operation reads validate the effective teaching/enrollment/membership tuple before returning private text. Observation DTOs echo that tuple and school for native projection checks. Observation history now counts and pages in SQL instead of loading all accumulated text.

A personal reusable phrase belongs to one account and tenant, independent of a student or school. Access requires FeedbackManage, an active account and a current verified teaching assignment in the explicitly selected school; that context grants no access to another owner's phrases. The same owner may reuse phrases through another effective teaching context. School managers and other teachers cannot read them by membership or a known identifier. Access after all teaching relationships end and retention/export remain D06 work; this does not grant former-teacher historical access.

Phrase roots and immutable revisions use two new tables. Each save, edit, archive or restore appends an operation-ID revision and atomically advances the root. Optimistic concurrency includes the expected current revision and concurrency stamp. The transaction follows the existing School then teacher-account barrier, which also serializes this owner's cross-school writes; paired owner/root/revision foreign keys and unique revision sequences protect associations. Exact operation recovery returns that immutable receipt even if a later revision exists; different content cannot reuse its operation ID. New roots cannot start archived. Archive removes a phrase from the default selector while retaining its body and history; it is not deletion or erasure.

The initial text limit reuses feedback's 4000 characters; list pages reuse the existing server maximum of 100, with 20 rows in each native view. No new provider, permission, model call or background worker is introduced. There is no automatic phrase creation from private observations, answers or published feedback. Phrases do not enter knowledge indexes, school sharing, learner notifications or assessment evidence. Teachers are told to keep reusable wording free of student identifiers and private judgments; the system does not claim automatic detection of those facts.

Native observations and phrases live in explicitly opened sections of the fixed single-student feedback editor. Observation save never creates or publishes feedback. Selecting one observation needs an explicit copy confirmation, then the teacher edits the separate public text and associates assessment facts. Selecting a phrase fetches its current non-archived version and replaces only local feedback text after confirmation, clearing an earlier observation selection. Later phrase changes do not rewrite copied or published feedback. Existing saved-version preview, recipient confirmation and all-associated-assessment full-review gates remain mandatory.

The native command runner reuses its account/tenant/API/app-scoped operation reference for five actions. Only identifiers and action persist; private text and exact retry payload remain in the running editor. A pending action prevents another action replacing it. Recovery is GET-only, explicit retry first queries the receipt and can resend only the original payload/ID; a missing receipt does not prove failure. Cold recovery needs no request text but cannot recreate a lost body. Closing tracking never undoes a server commit. Editing conflicts preserve local text and the original baseline; a comparison read does not silently rebase, and reread requires confirmation. Web keeps its existing typed session command and now also queries observation/phrase receipts before explicit retry.

Hide clears private native view rows and blocks late responses. Expiry hides unsaved text and permits explicit same-account reauthentication; logout, account change, effective teaching loss and unloading drop private text and retry bodies. No business text is written to native persistent storage. A Web handoff requires confirmed saves and no unsaved private text. Physical device erasure, SDK/WXML and weak-network acceptance remain independent checks.

Feedback and teacher-report responses now join the existing private/no-store filter, including conventional routes. Phrase write DTOs and revision entities join the Host audit ignored-type list; observation exclusions remain. This fixes missing response cache headers rather than treating current native memory policy as a browser-cache guarantee. Migration adds only the two phrase tables, their keys, indexes and restrictions. This slice does not complete AI feedback, voice, bulk individualized sending, WeChat subscription delivery, teacher trends or the full education PRD.
