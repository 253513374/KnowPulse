# Independent correction submissions and exact teacher reviews

Date: 2026-10-18. Status: accepted for the manual Web/service slice of PRD FR27. Extends the result-release and immutable-answer rules; does not change ADR 0029 material withdrawal or settle school exit/retention policy.

Follow-up: [ADR 0034](0034-unified-student-learning-schedule-and-workload.md) adds the unified student schedule and a small gate-protected correction work-state projection. The deferred workload item below records the original slice's boundary; review text remains absent from metadata.

A teacher assigns a correction to one fixed student and one actual graded frozen question. The task records its original assessment publication, sealed submission, grade root and current confirmed grade/release. Teacher draft, publication and withdrawal revisions are immutable. A private draft leaves the current publication active; replacement creates another fixed delivery, retaining old submitted copies and reviews. New publication needs an exact student/source preview and explicit confirmation that instructions are safe to share. Teacher operations require both assessment and learning management permissions plus current recorded school/teaching/student authority.

Student execution requires both participation permissions and the fixed active account/membership/enrollment. Original question, released answer/rubric and instructions are provided only under the current complete-review gate and unchanged captured confirmed grade. Metadata lists do not provide those bodies or record provision. Actual correction-body provision records only the displayed frozen question as a real review exposure; it must not mark all questions in a paper reviewed. Hidden/score-only releases, grade changes, replacement, withdrawal and time windows stop new execution as appropriate. Once the original confirmed grade changes, re-releasing results is insufficient: the teacher must publish a correction version tied to that grade. These gates do not delete a student's own submitted text/images; history and original operation receipts retain their separate current-identity authorization. They never reopen material bodies withdrawn under ADR 0029.

The student edits original thinking (optional), current solution and checking strategy. This slice uses explicitly labeled browser-local private drafts scoped to tenant/account/delivery. It is not the full cloud private-notebook capability. The base submission is captured on editing and retained after refresh. A different server head requires comparison and an explicit rebase, preserving local text/images. Before submitting, an exact preview binds content, selected confirmed image hashes, task publication, source grade/release, time window and student submission head. Explicit sharing creates an immutable teaching copy. Merely saving locally, previewing, uploading an image or a teacher opening progress does not submit private work. Persisted pending commands retain their original operation ID/payload; receipts are checked against their fingerprint, and unknown uploads require recovery or explicit abandonment. A refresh with a pending image requires reselecting the same file before retry, with its hash checked. This slice does not persist private binary files in the browser.

Correction images have a private container and immutable original bytes; rotation is reference metadata. Reservation, bounded upload and confirmation are separate. A teacher can download an image only if its ID occurs in a particular immutable submitted copy; unsubmitted uploads remain private. Reads verify current authority, stored length/hash and supported file signature. Current protection limits are five images per copy, 5 MB per image, 20 MB/40 reservations per delivery; these are development limits, not school retention/capacity policy or full codec/OCR validation.

Teacher review publishes NeedsRevision or Accepted and student-visible advice against the exact current submitted copy and review head. It requires explicit confirmation and the current original full-review/grade gate. A later submission does not inherit an earlier review as its own. Old reviews and operation receipts remain traceable. Student reads hide teacher review text while the original full-review/grade gate is closed. Original answers, confirmed marks, result releases and mastery evidence are never overwritten or automatically created by correction or review.

Six new tables use paired Restrict foreign keys for source/student/teacher, publication kinds, delivery/submission/review heads and predecessors, with sequence and shape constraints. Migration `20261017174449_AddIndependentCorrectionTasks` creates no historical assignments or corrections and refuses downgrade if any correction facts remain. The application rollback needs an explicit compatible restore. Audit exclusions cover private content/commands; result responses use private/no-store. Existing result projection and image primitives are reused, without new dependencies or provider types in contracts.

Authenticated browser/device and WeChat acceptance, full PostgreSQL application concurrency/Blob timing, cross-task workload integration, cloud notebooks, same-question practice histories, notices and D06 remain separate outstanding work. Relational migration/constraint checks and SQLite application tests are distinct evidence and do not certify those outstanding parts.

## Native student correction extension (2026-10-18)

The student workspace and unified workload now link to native correction lists and fixed-delivery detail. GetMyCorrectionListAsync adds an optional school filter before the candidate quota; the DTO echoes SchoolId. GetMyCorrectionForSchoolAsync checks the school before providing the original question or recording its exposure. Existing Web detail/list and the original 22 operations remain compatible; the interface now has 23. The new narrow GET image controller delegates exact delivery/attachment IDs to the original service with both existing participation permissions, private/no-store and disabled auditing. Multipart uploads use the original application endpoint. No migration, dependency, permission or source policy change is needed.

Native drafting requires explicit local-storage consent. It stores only self-written content, selected image references, the original submission base and exact pending request, scoped by app/account/school/delivery. The existing answer-storage account prefix and logout cleanup also cover correction drafts and copied originals. A 24-hour logical expiry is checked on subsequent use; logout/account changes attempt account-scoped cleanup, while an active correction page detecting identity/authority loss clears its own delivery content and copied images where storage permits. Cleanup failures are reported, not treated as proof of physical erasure. Original questions, model/source data and teacher advice are excluded from local drafts.

Images reuse signature/size/SHA-256 checks and the immutable operation-named copy. Upload confirmation does not submit to a teacher. Rotation/order/removal affect references only. Original-operation recovery precedes an explicit retry; a lost file must match the original bytes and stable name. Late copy/download responses cannot restore content after identity loss; own late copies are cleaned. Preview binds the exact submission content/head; edits and refresh invalidate it. A conflicting cloud submission requires explicit comparison/rebase. Confirmed copies and exact teacher reviews retain the original gates and independent-history semantics. The view shows one history copy at a time from a bounded page, and formal results remain separate.

Actual external WeChat/SDK/WXML, camera and physical devices, school retention, complete weak-network/browser flows and full production/application concurrency remain outstanding. Local Page scripts with real signed HTTPS, PostgreSQL and MinIO are distinct evidence and do not settle those gates.
