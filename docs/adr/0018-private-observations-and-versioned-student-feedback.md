# Separate private observations from versioned student feedback

Date: 2026-10-14. Status: accepted for implementation. Verification is recorded in the implementation log.

Inbox follow-up: [ADR 0049](0049-student-inbox-and-independent-feedback-message-reading.md) adds a separate generic-message read timestamp and school-scoped body opening. The existing version body-read fact and original public operations remain unchanged.

FR19/FR20/FR28 distinguish the teacher's private observation from feedback addressed to a single student. An observation is an immutable, owner-only journal entry; a correction is another entry. Selecting its text creates an independent feedback draft. No visibility flag, school membership or teaching permission turns the original observation into public content. Personal knowledge indexes and exports do not ingest these teaching records.

Feedback binds a verified teaching assignment, student enrollment and school membership. Its recipient and subject cannot be edited; changing the student creates a new feedback record. Names are captured for identification. Current teaching, school/term, enrollment and active accounts are verified before writes. Writes follow School, teacher account, student account and feedback root; student opens follow School and their own account. The shared school barrier serializes access changes, publication and withdrawal. Historical access after leaving school remains D06; this implementation requires current relations for teaching reads and student reads.

Every save, publication and withdrawal has a stable operation ID and immutable revision. A draft preserves the current public version. Publication requires a preview of the saved current draft, explicit recipient/content confirmation, a matching concurrency token and unchanged assessment release references. A correction or withdrawal requires a reason. Retrying the original operation restores that revision rather than returning a later draft. The browser preserves the complete pending command before sending and retains it after an uncertain response or denied retry.

The native editor persists only the feedback root, operation ID and action in an account/tenant/app-scoped recovery reference; exact request text remains in that running editor. Explicit retry checks the original receipt first and never substitutes a new operation. Expiry hides private text and allows explicit same-account reauthentication; logout, account change, permission loss or unloading drops it. Process loss cannot restore an unsaved body or replay a lost request body. A missing first-save root or receipt returns null only after account and functional authorization; it exposes no learner content, grants no write permission and does not prove failure. Existing roots retain the same owner/current-relation checks. New recipient resolution uses the current verified teaching/enrollment/membership triple without creating feedback. Native Web handoff opens only the same confirmed saved root through normal Web authentication.

Each revision explicitly binds at most ten published assessment recipient facts from the same teacher, student, class and subject. Assessment feedback requires a binding. Daily and period feedback may also reference assessments; every such reference must open full review before the text or evidence links are returned. This is checked against the current official release and UTC time on every read, including notifications. Saving or publishing a comment never changes assessment visibility. Explicit association and teacher confirmation are required; the system does not claim it can recognize every assessment fact in free text.

The student contract is separate from the teacher contract. Cards contain identity, version and read metadata; only an explicit authorized open returns public text and permitted recipient links. It never returns drafts, observation identifiers, private sources or internal reasons. Withdrawal returns a generic record without old text. A stale open version fails rather than silently reading another version. Existing content already seen or copied cannot be erased by withdrawal.

Cards add school ID/name metadata for the selected native school. An optional school filter is applied before authorization-aware counts and pagination for both cards and notices; it grants no access and does not mark a version read.

Read receipts are unique per public revision, including a withdrawal record. Listing a card or creating a notice does not mark it read; opening the current version records its first open time. Old-version reads do not mark corrections read. A notice has the revision ID, recipient, kind and time, with no body, score, diagnosis or observation text. Notices and first-open facts are separate from the publication fact; pending review gates suppress student access. These local notices do not claim WeChat delivery or authorization.

Six tables cover private observations, feedback roots, immutable revisions, explicit assessment bindings, version reads and body-free notices. Static paired foreign keys preserve teacher/enrollment/student and revision/recipient associations; all deletes restrict. Generic audit serialization excludes observation text, feedback bodies and correction/withdrawal reasons. No model service, notification provider or background worker is needed for this manual flow. Personal reusable phrases, actual WeChat clients/delivery, report analysis and the teaching-plan loop remain separate PRD work.

The mobile private-observation extension and personal reusable phrases are now specified by [ADR 0038](0038-owner-private-feedback-phrases-and-native-observations.md). They retain the independent-feedback and owner-only observation boundary above; remaining actual WeChat/device, policy and full-product acceptance is recorded separately.
