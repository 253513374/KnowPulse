# Capture authorized facts and atomically publish versioned teacher learning reports

Date: 2026-10-17. Status: accepted for implementation. Verification is recorded in the implementation progress document.

ADR 0019/0020 calculations and evidence decisions now feed actual teacher reports. `AnalysisManage` is a separate functional permission; the caller must also be the recorded report owner, have an active account and hold the current school/term/class/subject teaching relationship. Student or other-teacher access does not follow from knowing a report, snapshot or operation ID. School subject-rule management additionally requires `SchoolManage` and a current manager membership in that school.

A report fixes its owner, teaching assignment, textbook, UTC half-open window and optional selected task IDs. The window cannot be in the future or exceed 730 days. Capture resolves the current explicit textbook selection and mapping revisions, current active class roster and the owner's published overlapping tasks. Closed absence, not started, in progress, awaiting sealing, pending grading, scored and submissions outside the window remain distinct. Pending or absent papers never become zero-score observations. Task status is the status at capture time; this is not historical operational-state replay as of the window end.

Captured scoring uses only current complete confirmed question-grade revisions and their frozen definitions and conserving mapping evidence. Drafts do not replace confirmed marks. Qualifications, original relations and exact delivered exposure/context review versions remain separate inputs. Complete minimal same-school/subject attempt history, including earlier ungraded, abandoned and soft-deleted history and known connected originals outside the selected tasks/window, prevents repeated questions becoming independent evidence. This history contains identifiers/order/time, not other teachers' private answers or material. Known original grouping is not a content access grant.

The immutable source contains selected curriculum facts, minimal authorized student identities, confirmed attributed scores, evidence versions, minimal history and body-free exposure metadata. It excludes answers, scoring rubrics, private feedback, qualification reasons and source material text. A semantic fingerprint covers relevant current facts and versions, excluding no-op concurrency stamps, capture time and unconfirmed grading drafts. A metadata-only recapture computes the same fingerprint without loading confirmed score bodies. Source serialization has a 32 MiB UTF-8 limit; per-student results have an 8 MiB limit and a whole job has a 128 MiB result limit. Row/task/history quotas reject excess rather than silently truncate.

Subject rules have a school/subject root and immutable decision revisions, stable operation receipts and optimistic concurrency. The manager explicitly confirms the adopted policy, rationale, maximum window, minimum independent questions and assessments, recency and target ratio. Targets are greater than zero and at most one with at most four decimals. There is no invented school threshold. Disabling retains a decision revision but supplies no active calculation rule. Missing/disabled rules leave valid ratios insufficient; no valid evidence remains null/unassessed.

One report job captures one immutable source and generation. Jobs keep bounded automatic retries, exponential delay, a two-minute lease, run ownership, monotone progress, heartbeat and controlled failure stage. Explicit recovery creates a new job with `RetryOfJobId` and the same captured source only if that source is still current. Capacity failures require a narrower new report; they do not repeat automatically. An explicit refresh captures current facts and can reconfirm mappings within the same fixed teaching/textbook/window. Old or expired runs cannot complete a newer job.

The Host registers a separate report worker. Every five seconds it polls pending work and source checks, switches into each recorded tenant and validates the recorded owner facts without impersonating a user. Completed/terminal report sources become eligible for a check after 30 seconds. Semantic changes queue a new generation once; report reads validate current sources immediately, independent of this polling delay. This periodic check is a recovery mechanism, not an event-delivery or latency guarantee. No AI provider is needed for report calculation.

Capture takes School, recorded owner account and relevant task barriers, including the task barrier used by the independent cutoff/grading worker. Before publication it recaptures current metadata under the same barriers, checks the current root/job/run and inserts the class snapshot and all individual rows before switching the current pointer in one relational transaction. Changed sources stop the job; failed partial writes roll back. Previous immutable snapshots remain stored, but current reads hide outdated data. Every student/detail/evidence page supplies its expected snapshot ID, so pagination cannot mix generations.

Six new persistence types represent rule roots/revisions, report roots/jobs and class/student snapshots. Static scope pairing keys and 19 Restrict foreign keys protect owner, teaching, class, enrollment, membership, job generation and current pointers. Migration adds two parent alternate keys and does not rewrite existing rows or change nullable historical definition references. Domain/application checks still validate semantic source facts beyond database foreign keys.

The teacher Web page requests and lists reports, checks progress, displays class and student evidence and links question inclusion/exclusion decisions back to actual grading/evidence records. School managers have a rule editor. Writes save account/tenant-bound typed commands in session storage before sending; receipt lookup and exact retry remain separate from fresh computation. Discarding a local command requires an explicit UI confirmation and does not undo a server commit. Generic audit serialization excludes report bodies and policy reasons, and worker logs retain only controlled metadata.

Teacher reports may include confirmed grades before student result release. They are therefore never a student growth API. Student results continue to follow ADR 0017's current official release and Hidden/ScoreOnly/FullReview gates. Student growth projections, comparable longitudinal trends, teacher-confirmed personalized plans, activity/correction/reassessment, real WeChat pages, calibrated school policies and production concurrency/performance/device acceptance remain separate required work.

The separate bounded student projection and Web entry are now described by [ADR 0022](0022-student-growth-from-current-open-official-results.md). This does not turn teacher snapshots into student responses or establish the remaining full-product acceptance.

## Native teacher read extension (2026-10-18)

The teacher workspace now reads existing reports by its selected school and effective teaching assignment. GetListAsync accepts an optional school check; list/detail metadata echoes SchoolId and TeachingAssignmentId. GetForSchoolAsync checks both against the owned current report before loading report source/summary data. Existing Web list/detail calls and the original nine operations remain compatible; the report interface now has ten operations. AnalysisManage, current account, ownership and recorded effective teaching authority remain required. No new permission, schema, migration or provider dependency is introduced.

The detail DTO adds nullable Coverage calculated from all student summaries in the same immutable snapshot, before the existing response removes its unpaged Students list. It separates current student count and students with any complete confirmed score from assigned/scored/not-started/in-progress/awaiting-seal/pending-grading/absent/outside-window student-assessment pairs. It does not infer totals from a returned page, count missing work as zero or treat confirmed scores as qualified independent evidence. Stale snapshots return no coverage, just as they return no summary/current snapshot identifier.

Native class, student and point-evidence pages whitelist report facts and reuse the current server calculation/rules. No evidence shows an unavailable fraction, not 0/0; genuine valid zero remains zero. Rule revision/conditions and evidence inclusion/exclusion remain visible, without answer bodies, private qualification reasons or an invented client threshold. Request generation and displayed snapshot generation are distinct: an earlier snapshot may remain semantically current while a new request calculates the same source. Every child and paging action rechecks the selected scope/current snapshot and never silently substitutes another generation. Point/student/task cards are bounded to 20 view rows; large raw student evidence sets are not serialized to the native view.

The pages issue report GETs only, keep no persistent business cache and clear private views on hide/context/authority changes. Read UoW concurrency can return 409 while the report worker holds source barriers; the page clears the result and offers a manual refresh without automatic retries, new report requests or stale fallback. Known source-change/capacity failures are distinct from authorization loss. Web evidence review links additionally require AssessmentManage and carry only the exact grade-root identifier. Web report creation/recomputation remains an explicit general entry, not a credential-bearing or promised exact-snapshot handoff.

Teacher reads can precede student result release and do not publish it or record student answer exposure. Grade replacement, rule revisions and qualification changes require new current snapshots; old immutable rows remain traceable without retaining online authority after a teaching relationship ends. ADR 0043 adds class/individual trends and exact-assessment point evidence from these current snapshots and immutable paper metadata without changing this source schema. Real external WeChat/SDK/WXML/devices, complete weak-network/browser flows, school policy calibration and full production/application concurrency remain separate acceptance work.
