# Private notebook source pointers retain no source grant

Date: 2026-10-18. Status: accepted for the manual Web/service slice. Extends ADR 0008 and FR26, follows the D03 decision in ADR 0029, and preserves assessment result/exposure rules in ADRs 0017 and 0019.

Native own-note editing, command receipts and exact-version source navigation subsequently extend this decision in [ADR 0041](0041-private-native-notebooks-and-immutable-command-receipts.md). Its new receipt table does not replace this pointer representation or grant source access; the no-migration statement below describes this original pointer slice.

A note owner may explicitly link a particular owned note version to their own frozen assessment question or already-provided standalone material study task. The pointer records the source kind, fixed recipient, exact task publication/revision and frozen question/material component. It stores no source title/body, answer, rubric, private-library/share/blob provenance or permanent permission snapshot. Only the owner, with PersonalLibrary and an active account in the same tenant, may list/change/recover these associations. A teacher, school manager or operator does not inherit access.

Assessment metadata is available only while the current own result permits full review and the recorded student membership/enrollment remains valid. Material metadata requires the exact current authorized publication, actual prior provision and current source/share/student-use/download gates as applicable. Internal non-remote metadata seams reuse those source services' authorization in read-only units of work; they do not acquire the school/account write barriers reserved for real provision/exposure or mutation. Listing, previewing, adding, exporting or recovering a reference does not record review exposure, first provision, progress, submission, scoring or mastery. Opening a link goes through the real task and its current gates. An unavailable reference retains only its private identifiers; no old title or source body is returned. D03 withdrawal blocks the original shared body and attachment reads even after prior provision; it does not delete the independently owned note or explicit submitted teaching record.

References are bounded private bookmark metadata in the existing KnowledgeItem ExtraProperties JSON string. They are not authoritative relationships and have no source foreign key: source deletion may leave a dangling pointer, which resolves unavailable. Every operation rechecks the owned item and that its note version belongs to that item/tenant; no source pointer is trusted as an access grant. This deliberately reuses the account-owned knowledge aggregate instead of adding another notebook table. There is no schema change or migration. A note has at most 200 historical reference records, at most 20 active per version, and a bounded JSON payload. Removed records remain as private operation tombstones; they are never silently pruned. If long-term bookmark volume needs to exceed this limit, a dedicated persisted collection and retention policy will need a later decision.

Add/remove use stable caller operation IDs, canonical request fingerprints and the existing item concurrency stamp. An exact retry finds the original operation before checking the old stamp or source availability, while still rechecking note ownership/account/permission. Different stale commands cannot overwrite another item update. Removal can succeed after source authorization is lost. Operation lookup is owner-only and does not grant source access. The Web view retains only command identifiers/stamp in a tenant/account/item/version-scoped browser session receipt; uncertain operations can be queried or retried without minting another ID. Closing that browser session is not durable receipt storage, and the UI states this limit.

Own-library export includes active opaque pointers per exported note version and a RequiresCurrentAuthorization flag. It performs no source body reads and exports no source title, availability assertion, request fingerprints or concurrency stamps. A withdrawn/unavailable bookmark may remain in the archive but cannot reopen its source. Existing source-consistency checks include the owning item's stamp. Private source service responses use private/no-store, and DTOs are excluded from generic parameter auditing. Per-source authority is rechecked one at a time, not an atomic cross-source permission snapshot; subsequent opens always recheck again.

This does not implement same-question practice, automatic copying/summarization, teacher access to notes, reference-based content search, WeChat clients, school exit/retention rules or recall of already viewed/downloaded content. Device/browser acceptance and PostgreSQL concurrency remain separate from SQLite/service tests.
