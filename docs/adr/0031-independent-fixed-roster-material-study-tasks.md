# Independent material study tasks with fixed recipients and separate student history

Date: 2026-10-18. Status: accepted for the service and compiled Web slice. Extends ADRs 0014, 0025, 0029 and 0030 and PRD FR25. Full authenticated browser, WeChat and application concurrency acceptance remain open.

Subsequent decision: ADR 0032 implements exact standalone material/frozen-question review. The original-only Unverified projection and missing-review limit below describe this slice's initial state; new captures use exact frozen-question scopes and current paired decisions, without rewriting old snapshots or other exposure kinds.

Teachers can assign material learning before any exam, report or individual teaching plan exists. This requires its own task and immutable draft/published/withdrawn revisions, rather than invented assessment/plan identifiers or the enterprise employee learning-path permission model. LearningManage authorizes the current teacher's task management; LearningParticipate authorizes students. Source selection and teacher source inspection also require PersonalLibrary. These paths do not require AnalysisManage or TeachingPlanView. The existing curriculum resolver, current class roster query and exact material delivery module are reused through internal, non-HTTP methods; each caller retains responsibility for recipient, publication and transaction checks.

Every publication freezes the confirmed textbook/knowledge-point scope, student-safe instructions, execution window, exact material/version/share references, selected attachments and a previewed roster. The roster fingerprint includes membership/enrollment periods and account names; publication takes School, teacher account and sorted student account barriers, then rechecks the roster. Students added later are not added to that version. A new draft does not withdraw an existing publication. Replacement creates a new publication and new fixed recipients; older recipients retain their own submissions, but cannot read or execute the old materials. Replacement or withdrawal after a publication requires an explicitly student-visible reason. A later private draft cannot replace that public reason or reveal its private title to previous recipients.

Task listing, recipient preview and teacher progress do not mark materials as provided or started. An authorized student opening the available task body records actual FirstProvidedAtUtc; future tasks expose metadata only. Reading, downloading and self-reported completion are activity facts, never marks or mastery evidence. Started, completed and difficulty reports form an append-only student journal. Completion requires a preceding start and explicit activity-only confirmation; shared text requires explicit sharing. Restarting a completed activity requires an explanation. After the deadline, the current task can still offer materials and difficulty reports, while new start/completion is rejected. Timing remains server-authoritative; no new exception/resume policy is inferred from D07.

The whole recipient journal and student journal have separate heads. A teacher follow-up replies to the exact current student difficulty, advances only the whole journal and stores a private note; the student sees only a matching handled time. Stale student/head or whole-journal/concurrency expectations are rejected. Commands carry account-scoped operation IDs and exact fingerprints. Receipts are recovered before execution/publication/time/material gates, but still require current actor, tenant and teaching/student relations. Browser pending commands are stored in sessionStorage before sending, separated by account/tenant and by task where applicable; failures retain the original command for query/resend or explicit abandonment. This is temporary recovery storage, not a confidential storage or device-erasure guarantee.

All material delivery uses ADR 0030's common exact-source checks. A school author must explicitly grant AssignToStudents; attachments additionally require Download. Student requests never obtain source library/search authority or raw source identifiers. Each body/download checks the fixed recipient, current publication, current relationship and source authority. Downloads recheck the parent after opening Blob storage and source authority before returning. D03 stops later online reads even after prior delivery; original student text, completion facts and receipts survive. A provided current recipient may still report material-unavailable difficulty. Current account/relationship restrictions also apply to history; D06 historical access after leaving school remains undecided.

Actual task provision is also an analysis context. Same-school/subject deliveries overlapping a frozen question's positive knowledge-point scope enter the existing source fingerprint as Unverified exposures, with stable recipient/question identifiers and actual provision time. Material text and source identifiers are not copied into analysis manifests. Withdrawn/replaced tasks and soft-deleted roots do not erase actual historical contact. Connected originals and novelty checks without frozen weights conservatively use the confirmed target scope. Exact standalone-task hint review is not yet implemented: these contacts cannot currently be cleared into independent reassessment evidence, and can prevent a new formal-activity novelty confirmation. This deliberate limit must remain visible until an exact, versioned review flow exists; do not silently treat unknown contact as no hints or fabricate grade evidence.

Migration 20261017162737_AddIndependentMaterialStudyTasks adds four new tables without backfilling assignments or altering old scores. Paired Restrict foreign keys bind teacher/class/term/subject/book authority, revisions and publication kinds, each fixed recipient's membership/enrollment, and journal parents; sequence uniqueness and action/actor constraints protect the public/private split. UTC conversions follow the existing provider pattern. Schema downgrade refuses when any study task/history remains, rather than deleting student records; application rollback needs an explicit compatible restore. Real PostgreSQL migration/constraint evidence is distinct from service authorization exercised through SQLite integration tests and does not prove full PostgreSQL application concurrency or capacity.

## Native material learning extension (2026-10-18)

The one-AppID student workspace reuses the same task, material delivery and append-only progress services. Listing accepts an optional SchoolId filter before capacity/count/paging; the public student DTO returns that authorized school identifier. OpenMyForSchool verifies the expected school before recording provision. OpenMy keeps its original single-recipient signature and generated HTTP path: adding a second ID to that method changes ABP routing and breaks existing Web callers. The native-only method has a separate conventional path. No database change is required.

A private/no-store, audit-disabled GET attachment controller delegates all three identifiers to DownloadMyMaterialAsync, preserving current parent/source checks after Blob access. It does not expose a storage URL or another attachment. The native reader projects plain text and selected file metadata, reauthorizes every download, and discards late responses after hide or identity-context refresh. It attempts deletion only of its owned tempfiles. Document renderer caches, offline copies and physical erasure remain outside this guarantee and require actual-device acceptance.

Student progress persists only an operation reference before sending; exact text remains in the running page. Uncertain operations query their original receipt first; explicit retry keeps the original payload and student head. Leaving drops the retry body, while the reference remains recoverable after reauthentication and current authorization. Cloud revision changes do not rebase typed text. Bounded StudyTask editing-rule errors retain the verified identity; true material/recipient authorization refusals still clear projections. This extends the existing D03 and activity-only semantics; it adds no mastery inference or source-reading right.
