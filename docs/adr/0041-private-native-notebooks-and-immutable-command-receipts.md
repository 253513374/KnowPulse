# Account-owned native notebooks and immutable command receipts

Date: 2026-10-18. Status: accepted for the local service/native slice. Extends ADRs 0008, 0035 and 0040; preserves D02 (one AppID, two workspaces) and D03 (withdraw future source reads, retain independent history).

Teachers and students enter the same account-owned private notebook from the workspace, independently of a current school role. PersonalLibrary, an active account, tenant and actual note ownership are checked by every service operation. School membership is not a grant to another person's notes and school exit does not transfer or delete these personal assets. Assessment, material provision, teaching submissions and mastery remain separate facts.

Reuse KnowledgeItem with material type Note, KnowledgeVersion and KnowledgeAttachment/BlobStoring. Creating a note saves its root and first version atomically; saving appends a new immutable body snapshot and updates its metadata under the root concurrency stamp and expected latest-version ID. The shared personal-version append path locks the same root for legacy Web callers, advances from the maximum version number including soft-deleted rows, and never reuses an old number. Organization-owned legacy version creation retains its previous concurrency behavior. The Web editor refreshes its own root stamp after a successful append without overwriting an independently dirty organization form.

PersonalNotebookCommand stores immutable, owner-scoped create/save/upload/delete receipts with stable operation IDs and request fingerprints. It stores identifiers, kind, version number, time and, for files, size/hash; no title, body or filename. Same-ID/same-input retries find the original receipt before stale-head validation, never restoring the old head. New stale saves fail without overwriting any body. Note soft deletion permits owner-only metadata receipt recovery, not deleted-body access. Commands have no artificial per-note editing limit. Migration 20261018053435 adds one table, three restrictive foreign keys, an owner index and non-null-aware shape constraints; Down refuses a nonempty receipt history before dropping it. This does not determine the pending production retention policy.

Attachment upload reuses the existing bounded personal-file policy and version/count barrier, and records its receipt in the same attachment transaction. The operation ID is the immutable attachment ID. An already-written orphan Blob is completed only if its actual size/hash match; conflicting original bytes are never overwritten or deleted. A custom authenticated multipart adapter accepts the percent-encoded original filename in a header, validates it, and delegates to the application service. Downloads recheck owner/account after obtaining the stream and dispose it on denial. No public Blob URL is introduced.

The two native pages provide bounded metadata/filter lists, one selected body, version history, original attachments, explicit deletion and ADR 0035 source associations. Metadata, versions, files and source rows are displayed in pages of 20; own body remains limited to 8192 characters. Private draft/original-command/file retention needs explicit local consent, is scoped by API/app/client and tenant/account, and is logically limited to 24 hours. Logout/identity/permission loss strips private payloads and attempts removal of application-owned file copies, retaining identifier-only recovery. Cleanup failure is explicit; physical erasure and device acceptance are separate. A lost command is queried before a retry; original text/name loss prevents reconstruction. Retrying a file requires its original bytes and original metadata. Closing local tracking cannot undo a committed server fact.

Source references still carry only typed recipient/version/component identifiers. SchoolId is dynamic navigation metadata returned only while the source is available; it is not persisted as a grant. Creation recovery retains the incoming source identifiers without adding a reference automatically. The native preview rejects a different incoming publication/revision before showing or linking it, and Add rechecks that exact pointer. Explicit source navigation pins the expected assessment revision or study publication; the source service rejects a mismatch before question feedback/exposure or material provision. Preview/list/add/receipt recovery do not record exposure, progress or grading. An unavailable source hides its title/navigation metadata while leaving the own note and its history intact.

Private notebook responses use private/no-store. Content DTOs and file transfers are excluded from generic parameter auditing; audit URLs omit private notebook/library search query strings. The native file bridge reuses existing authorized downloads and common image/PDF/Office preview handling, with original file selection through wx.chooseMessageFile. Unsupported previews use the existing independently authenticated notebook Web entry; unsaved device text is not synchronized. Existing Web editing remains on its legacy APIs and does not acquire native command receipts by implication.

Real WeChat credentials/domains, SDK/WXML rendering, physical devices/cameras, full weak-network/browser coverage, operational retention and production concurrency/capacity remain outside this local slice's acceptance. No provider, worker, permission or dependency is added. The complete education PRD remains active.
