# Review the exact saved submission and explicitly confirm exclusions

Native extension, 2026-10-18: preflight and explicit start are separate, and start recovery queries the current fixed recipient before retrying the original operation. A concurrent start rejection is not an empty successful attempt. The native editor exposes sequential draft synchronization or an exact saved-only review with paged question headers, local draft exclusions and unlinked upload facts. Saved-only submission requires its separate choice and a second confirmation. All edits/refreshes invalidate that review. Recovery accepts the one actual sealing winner and labels manual versus deadline cause, without attributing another operation to the current button. The displayed countdown estimates server time and never sends an automatic late save or claims cutoff was committed; current receipt/background facts remain authoritative. True authorization denial still fails closed, while a bounded editing-rule rejection keeps the exact pending command and private draft for explicit recovery. Native Page/platform and actual local HTTPS/PostgreSQL/Blob checks are distinct from SDK/WXML/device and browser-click acceptance.

Date: 2026-10-17. Status: accepted for the Web/service slice. Extends ADRs 0014–0027 and PRD FR24; authenticated browser/WeChat acceptance remains open.

Manual submission before the deadline now requires a server preflight of the student's own current response set and image-upload facts. It reports safe question headers, empty answers, missing blanks, linked image counts and every upload not linked to a current saved answer. Replaced/historical uploads are described as unlinked, not automatically as failed. A fingerprint covers the frozen paper, response heads and all reserved/confirmed image operations. Saving or uploading after review invalidates the fingerprint, including uploads that do not change the response-set version. The school, student and attempt write barriers protect a coherent read; sealing retains its original parent CAS and immutable manifest.

The page first offers sequential synchronization of local question drafts, stopping on a conflict or unknown operation without discarding remaining drafts. The alternative lists the actual local question drafts, failed/abandoned selections and server upload exclusions, requires an explicit saved-only choice and a second confirmation, and keeps local drafts after sealing. Local persistence or server refresh invalidates the displayed review and its choice. An unknown operation must be recovered, retried exactly or explicitly abandoned before another operation; it is never silently rewritten to obtain a new fingerprint.

New manual commands require review even though the input field remains nullable for exact recovery of old committed operation fingerprints. Existing submission recovery precedes new-write checks. Deadline sealing, including crossing the cutoff during preflight, uses persisted saved facts without requiring a fresh client confirmation. Preview contains no answer text, grading keys or material body; generic audit excludes its DTO. No schema or package change is required. Linked client-state and actual service integration tests cover these rules; they are not authenticated browser, PostgreSQL concurrency or device-capacity acceptance.
