# Native student growth preserves school, snapshot and result-release boundaries

Date: 2026-10-18. Status: accepted for the native/local verification slice. Extends ADRs 0017, 0021 and 0022, without replacing the student calculation, public snapshot representation or historical-access policy.

The student workspace adds school context selection, a subject/textbook growth overview and point-evidence drill-down. AssessmentParticipate and the caller's current student school workspace are mandatory. Three new scoped GET operations wrap the existing safe values with actual SchoolId. The source reader applies school filtering in SQL before its candidate quota, both initially and after acquiring the existing student barriers. Wrong-school growth/evidence requests fail before projection; all former unscoped Web methods and public snapshot fields remain unchanged. A matching Web/native request recovers the same deterministic immutable snapshot and calculation time. No schema, migration, permission, worker, provider or dependency is added.

Only the caller's currently score-open official releases enter the source. Teacher reports, hidden grade changes and unpublished results do not become student content or public version signals. Existing qualifications, original-question grouping, earlier attempts and exposure rules still determine independent evidence. A same-question repeat can have a comparable raw score without becoming a new independent question. No evidence remains unknown, genuine valid zero remains zero, and absence is not plotted as a zero. Missing school rules do not acquire a client threshold or a definitive mastery classification.

The native overview renders at most 20 score records and 20 point cards per view; context lists and evidence pages also display at most 20 rows. Existing source quotas and result size bounds remain explicit failures rather than silent truncation. Safe field projections exclude private grade/revision/source identifiers, teacher observations, answers, criteria and internal reasons. Score bars have text marks and all server-provided comparison limitations. They compare observed marks, not equated tests or intervention effects; no cross-subject ability total or peer ranking is produced.

Date selection is explicitly UTC and includes both selected calendar days. Historical end dates become the following midnight; today ends at the captured query instant. The resulting half-open timestamp window is fixed for pagination and navigation, subject to the source's current school rule and 730-day ceiling. Displayed window timestamps remain UTC; score/calculation timestamps follow the device timezone. A new explicit date query captures a new window, while rereading the same window keeps its exact endpoints.

Overview pagination and every evidence page revalidate the current source against the expected snapshot. Rule, visibility or score changes reject old pages; there is no mixed-generation fallback. Evidence additionally requires FullReview for each record. Score-only contributions may remain in the safe point overview but do not expose question IDs, per-question marks or exclusion labels; the evidence result only reports currently readable rows and a restricted-evidence indication.

Explicit original-result links include the expected result-release ID and, for review basis, the exact frozen question. The existing school-checked result endpoint accepts an optional expected release, rejecting mismatch before question feedback or exposure. The expectation is also carried through the existing review-barrier reread. Legacy and notebook callers that omit the expectation retain their previous behavior. Growth, context and mark-only evidence reads do not themselves record answer delivery; only the explicit authorized original-result open does so.

Pages reuse the existing read-scope lifecycle, keep no persistent business cache and clear private values on hide, account/context/permission changes and late responses. Known source, rule/window and capacity failures are distinct from authorization loss. A source-barrier 409 clears the view and offers a manual reread without automatic retry or old-snapshot fallback. The independently authenticated Web handoff contains no student, snapshot, grade or credentials and requires fresh context selection.

Existing private/no-store response filtering already recognizes the growth service; new wrapper DTOs are additionally excluded from generic parameter auditing. Ended student relations invalidate old online snapshot access, while stored facts remain for separately governed traceability. Historical reading/retention, calibrated school policies, comparable teacher trends, real WeChat/SDK/WXML/devices, full browser/weak-network behavior and production concurrency/capacity remain required acceptance work. Native Page-script/HTTP/SQL evidence must not be reported as those broader checks.
