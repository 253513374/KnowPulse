# Build student growth from current open official results

Date: 2026-10-17. Status: accepted for the student Web and bounded on-demand projection slice. Runtime, device and production-scale acceptance remain separate.

The subsequent native school-scoped client, unchanged Web/native snapshot semantics and release-pinned original-result navigation are described by [ADR 0042](0042-native-student-growth-with-school-and-release-pins.md). The original three operations remain available alongside three scoped operations; no additional snapshot table or migration is introduced.

Teacher reports under ADR 0021 can contain unreleased confirmed grades. Student growth therefore captures its own authorized source rather than exposing or trimming a completed teacher aggregate. Three `AssessmentParticipate` operations list the caller's available teaching contexts, calculate growth for a UTC window and read point evidence for an expected snapshot. They never accept a student user ID. The current active account, tenant, fixed assessment recipient, school, term, student membership and enrollment remain mandatory, matching the existing student result boundary.

Contexts are built only from the student's currently score-open official assessment releases. The source checks the current task publication, closure and release pointers and scheduled score/review times. Current teacher textbook selections, teacher report generation and the teacher's ability to sign in do not grant or remove the student's authorized official result access. A context separates school, term/class, teaching assignment and textbook; the UI groups by subject without merging subjects into an ability score.

Only exact grade references from the current official release items enter scoring. They must match the current confirmed grade roots and the frozen paper/definition, and their complete question totals must conserve the official submission total. No teacher drafts or hidden-task grading rows enter the student's calculation. Absence remains null and unassessed, not a zero-score paper. Window filtering uses submission effective time or the absence cutoff. The target point set comes from the frozen question mappings of score-open assessments in this context; the window selects scoring evidence rather than inventing a private current curriculum for students.

The existing calculator and evidence reader retain current qualifications, known original relations, complete minimal attempt history and body-free delivered exposure/context decisions. Earlier ungraded, abandoned or hidden attempts remain negative independence checks; opening a later score must not manufacture independent evidence. These private history identifiers and their raw version vectors are not public version signals. A grading or qualification change confined to a hidden task changes neither student growth content nor its snapshot ID. An explicit eligibility decision affecting a visible grade can still require its public evidence to be re-evaluated.

Public values contain only the caller's open assessment totals, context labels, opaque point aliases and point revision numbers, valid score ratios, evidence quantities/gaps, window, calculation time/version and adopted rule values. They exclude tenant/student/enrollment identifiers, internal curriculum mapping and grade-revision identifiers, private sources, qualification reasons, observations, answers, rubrics and teacher feedback. School rule reasons stay private. Missing or disabled rules keep valid ratios insufficient; no valid evidence remains null. Real zero is valid evidence and is not converted to absence.

Per-question evidence additionally requires the current `FullReview` gate. Score-only contributions can appear in the permitted point overview, but their question IDs, per-question marks and exclusion labels are withheld. The evidence page reports only review-open rows and a restricted-evidence indication. Its links use the existing authorized result endpoint for answers/rubrics, which records delivery under ADR 0019. Growth and mark-only basis reads do not themselves claim that answers were delivered.

A bounded on-demand calculation publishes one immutable student snapshot in its relational transaction. The source takes School, student-account and relevant task barriers, rereads current publication/access and uses no fake user identity. A deterministic ID and a unique student/context/window/source index make a repeat of the same calculation recover its committed version and calculation time. The fingerprint covers public values and visible grade/qualification/inclusion versions, not capture time or unrelated hidden history. A failed calculation exposes no partial result; retrying the same read can recover the complete version. There is no student background job or mutable current-pointer row in this slice.

Every basis request recaptures the same window, authorizes current relations/releases and checks the expected public fingerprint. Changed scoring, rules, eligibility or visibility rejects an old basis version until the overview is refreshed. Rehidden results or ended enrollment cannot be recovered through a stored snapshot ID. Old snapshots remain stored for traceability but are not exposed through a history/cache bypass API. MVC adds `private, no-store` and `no-cache` headers to growth responses through the service interface, independent of its conventional route name. Generic audit serialization excludes growth bodies and the internal source.

One new table stores the sanitized result JSON and its recorded scope. Four Restrict foreign keys pair the exact enrollment, membership, teaching relation and school/subject/textbook. A unique source-version index deliberately uses non-null student/context identity rather than nullable TenantId, so host-scope duplicates are also rejected. Tenant filtering and actor checks remain explicit. Existing rows and historical nullable definition references are unchanged.

The student Web shows open-score records, point estimates/revisions and gaps, links to authorized results and drill-down. Score connections require equal frozen point coverage, total maximum, nominal difficulty counts and exact frozen scoring basis; differences or missing marks are explicit. This is a conservative comparison of observed scores, not equated papers or proof of intervention effects. Same-paper repeats remain practice even when their raw marks can be compared. A text table accompanies the SVG plot.

Quotas from the report source and the 8 MiB student result bound apply; exceeding them fails explicitly rather than truncating. This synchronous projection and its stored versions have not established production latency, storage-retention policy, full multi-Host application concurrency or a large-load recovery strategy. Independent SQL transaction checks and SQLite integration tests do not prove those requirements. Historical access/retention decisions, broader comparable teacher trends, teacher-confirmed plans, learning/correction/reassessment and real WeChat execution remain required parts of the original goal.
