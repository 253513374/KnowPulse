# Freeze activity material grants and require explicit author consent for student use

Date: 2026-10-17. Status: accepted for the service and compiled Web slice. Extends ADRs 0009, 0023–0029 and PRD FR25. Authenticated browser, real devices and full application concurrency acceptance remain open.

Materials are exact references inside the existing immutable plan revision, bound to a nonformal step and its assigned student. Each records a stable reference ID, display name, source item/version, optional original school share and selected attachment IDs. Saving, confirming and publishing revalidate source rights; editing creates a new plan version rather than replacing a previously delivered source. There is no copied student library item or general student library/search grant. References are limited to 50 per plan, 10 per step and 10 selected attachments; teacher source pages are paged and attachment preview reads at most 201 rows to enforce a 200-file capacity boundary.

School sharing gains an explicit AssignToStudents purpose (32), initially unchecked. Read remains required; attachment delivery additionally requires Download. Retrieval, generation and export are independent. Old values are unchanged. The existing relational query is shared by teacher use and the internal exact-assignment path, verifying tenant, coherent library/item/version ownership, published lifecycle, school, active author/assigning-teacher accounts and teacher memberships. The student path can only invoke it after verifying that student's current assigned activity and current provided plan publication; it never exposes an unrestricted student share query. Direct author assignments use the author's private ownership authority rather than an unrelated school share.

The public plan contains only reference ID, step and teacher-confirmed display name. Source IDs, library/share/owner IDs and blob paths remain teacher/internal data. Material reads and downloads require TeachingPlanView plus LearningParticipate, current student relations, provided activity, current publication and existing plan/result gates. Downloads accept only the selected attachment IDs, check current authority before opening storage and again before returning the stream, and use controlled storage-failure errors. Responses are private/no-store, use existing BlobStoring and stream-download facilities, and are excluded from generic body auditing. A request already delivered or an in-flight authorized stream is not a recall guarantee.

Withdrawal of the exact supporting share blocks subsequent body and attachment reads even after an earlier open. Missing/inactive source facts or missing selected metadata also block access. The activity is displayed as blocked and new start/completion commands fail; an already provided current activity can still report difficulty. Existing student actions, handed-in text, old operation receipts, grades and historical submissions remain unchanged under their own access rules. Remaining workload uses submitted completion facts, not the current material-read label. Reading does not write completion, scores or mastery. A new no-hints confirmation/re-enabled formal context must also verify the referenced exact materials; teachers can inspect them in the plan, progress, hint and formal-preview screens.

Empty material lists are omitted from the historical plan codec and command hash. This preserves existing content bytes, exact old fingerprints and confirmation/publication comparisons; an old missing list reads as empty. Nonempty references are included in the immutable content and fingerprint. Migration 20261017152215_AllowExplicitStudentMaterialSharing only widens the existing purpose constraint from 31 to 63; it grants no new purpose to old rows. PostgreSQL downgrade rejects new-purpose rows atomically rather than silently stripping consent. Schema downgrade is not proof that an old application can read new nonempty material JSON: application rollback requires explicit compatibility/data review or a matching restore, without deleting student histories.

This implements exact plan-activity material delivery and D03 for grants depending on a school share. Independent learning assignments, broader student history discovery, WeChat, copyright/retention/exit policies and production capacity remain separate work. Real PostgreSQL evidence covers migration/purpose constraints and rollback boundaries; service authorization behavior is exercised through EF/SQLite integration and does not prove PostgreSQL application concurrency.

## Native exact-activity delivery (2026-10-18)

The native plan page uses the existing authorized material read and a narrow GET attachment wrapper at /api/education/teaching/activities/{activityId}/materials/{materialId}/attachments/{attachmentId}. The wrapper delegates those exact three identifiers to DownloadMyMaterialAsync, requires both existing permissions, disables body auditing and returns private/no-store. It grants no new library or source access. A revoked source body returns the existing unavailable envelope without content/attachments; a download is denied. The native projection exposes the existing material availability fact to stop new start/completion while preserving provided-activity difficulty and owned records.

Plan and independent-study pages share bounded Unicode-safe plain-text paging; complete source text stays in page memory and is cleared on hide. Selected common attachments retain the existing 20 MB native-preview limit and owned temporary-file cleanup attempts. Real local PostgreSQL/MinIO/HTTPS acceptance checks selected/unselected/other-student access, exact bytes, withdrawal and preserved original activity receipts. This does not prove actual WeChat document rendering, physical cache erasure, concurrent stream recall or production capacity.
