# Keep account-owned libraries separate from tenant-scoped school facts

Each existing ABP identity owns one default personal library in its recorded tenant. The library ID equals the globally unique user ID, and a database unique owner constraint includes soft-deleted records. Repeated initialization restores that same library; a tenant mismatch is rejected rather than silently moving assets. Items carry an immutable library/owner pair, validated by a composite foreign key. Existing organizational items retain both fields as null; migrations do not infer ownership from `CreatorId`.

New AI generation inputs, RAG calls and evaluations record an immutable personal owner even when retrieval returns no citations. Questions derived from personal inputs retain that owner after sources are removed. Owner checks supplement source, tenant and feature authorization; they do not grant permission to reuse an unavailable source. Newly frozen exam papers containing personal questions also retain their checked owner, so deleting a source does not prevent the owner from reading or grading historical snapshots. Legacy papers without a recoverable owner continue to recheck source access.

Schools are independent entities within the existing tenant, not departments or one tenant per teacher. Memberships, terms, classes, subjects, teaching assignments and enrollments reuse verified identity accounts. Relations use UTC half-open intervals, preserve ended records and require the corresponding membership to cover the relation. Classes are term snapshots. School configuration changes share a school concurrency token and a relational transaction so overlapping relation checks cannot both commit without revalidation. A platform permission does not substitute for a current school manager membership.

These are implementation choices for the first education foundation. Cross-tenant transfers, real school onboarding and historical access after leaving a school remain policy decisions. The owner-only policy never grants school sharing; separate version-bound authorization and retained shared indexes follow ADR 0007 and ADR 0009. Index completion remains pipeline-owned under ADR 0006; the former manual completion API rejects requests.

Personal prepared versions cannot change attachments; revisions use a new draft. Attachment size and count use the same server policy in the client, with development defaults rather than school commitments. Blob deletion follows successful metadata commit; failed cleanup may leave an inaccessible orphan file instead of destroying a file whose database transaction rolls back.
