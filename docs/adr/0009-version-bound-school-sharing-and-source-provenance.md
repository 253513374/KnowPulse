# Keep school sharing bound to an authorized version and retain its provenance

School sharing is an independent, explicitly selected authorization for one personal version in one school. It preserves the library and item owner and freezes the selected version title and an optional summary entered specifically for sharing. It never reads a later private item's summary into shared metadata. Reading, retrieval, question generation, attachment download and export are separate uses; generation also requires retrieval. Unsupported uses cannot be granted. New AI generation defaults to the personal library; including school sources requires an explicit scope choice. A saved generation task retains that choice when retried, while permissions are checked again.

ADR 0030 adds explicit AssignToStudents consent for exact activity assignments by an effective teacher. It is initially unchecked and grants no general student library/RAG access; attachments also require Download. Teacher retrieval and generation still use the original teacher-only access path. D03 blocks subsequent online reads relying on a withdrawn share while retaining separately authorized student submissions.

This decision adds a narrow exception to ADR 0005's invalidation of old indexes during atomic publication: a coherent published version with a live school share may retain its existing chunks, embeddings and jobs when the owner prepares a private revision. It uses the same version and indexing pipeline, not a copied public item or a second index system. Unshared old versions still become outdated. Retention and reindexing require the recorded tenant, item/library ownership, active author account, existing school and effective author teacher membership to agree. Withdraw, archive or deletion of the item still invalidates its indexes. Publication keeps version switching, applicable invalidation and new task creation in one relational transaction.

Index retention is a lifecycle condition, not reader authorization. Retrieval computes authorized exact version IDs from current relational facts before vector search and checks those facts again after each hit. Both the author and reader must be current teachers in the selected school, and the requested use must be granted. A shared older version is usable for retrieval or new question generation only with active published chunks and their fully indexed job. Revocation or membership expiry blocks new shared use even when stale vectors remain. Background indexing checks the version's current or shared lifetime throughout persistence, embedding and vector writes; complete means all pipeline stages succeeded under ADR 0006.

The borrowing teacher owns their generation tasks, adopted questions and frozen papers; the original material retains its owner. Source references that established a personal question's authorization remain attached when the teacher edits the question, so removing display citations cannot bypass a later revocation check. New adoption, review, paper construction and reuse recheck that provenance. A frozen historical paper retains its separately checked owner and snapshots as established by ADR 0008. ADR 0029 resolves the student-material portion of PRD D03: withdrawal stops subsequent online body/attachment reads for already assigned materials, while historical submissions remain under their own authorization. Remaining downloaded-copy and derivative-work policy is still open; this decision does not promise to recall content already seen.

Generic personal-item, version and attachment APIs remain owner-only. Shared readers use version-specific shared APIs and safe frozen metadata. Feature permissions, tenant checks and student result-field restrictions still apply independently. No external provider type enters contracts or domain objects, and vector data remains a rebuildable projection rather than an authorization source.
