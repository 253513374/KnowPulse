# KnowPulse 教师微信小程序产品规划

> **历史文档／已退役（2026-11-01）**：本文记录早期学校教育方案或当时的实现与验证，学校管理、学校身份核验和旧 `/education/*` 工作区已退出当前产品。文中的“已确认”“当前”及验收结果仅指原记录时点，不作为现行需求或可用功能承诺。当前方向以[教师出题与学生答题业务需求](../business-requirements.md)及[项目改造计划](../project-refactoring-plan.md)为准：教师使用 `/teacher/*`，学生使用平级独立 `KnowPulse.MiniProgram`。

日期：2026-10-06。状态：完整体验规划，原生身份、工作区与测评进度已部分实现；实际范围及验收见[实施记录](../education-implementation-progress.md)。配套阅读：[产品总规划](../education-product-plan.md)、[教师网页端](education-teacher-experience.md)、[学生小程序](education-student-experience.md)。

已确认：教师也拥有微信小程序，用于简单工作、数据分析查看和学生评语。本文的导航、页面与具体操作范围是首期设计建议；教师移动入口与学生移动入口共同构成完整首期，不能将教师小程序整体后置。

## 1. 产品定位与跨端分工

教师在课间、课堂巡视、课后辅导时，能快速知道哪些任务需要跟进、学生目前有什么学习证据，并给出具体反馈。手机上的工作与网页端共用同一任务、评语和学情版本；切换设备不要求重新创建记录。

| 场景 | 教师小程序 | 教师网页端 |
| --- | --- | --- |
| 今日工作 | 查看待办、任务要求和提交进度，按学生催办，打开学生记录 | 创建和管理完整教学任务、调整复杂规则 |
| 教学积累 | 查阅本人或获授权资料，保存简短教学随记 | 批量上传、整理附件、管理版本与学校共享 |
| 学情分析 | 查看班级概览、学生学科成绩及证据，下钻知识点 | 多维对比、完整证据分析、导出与批量处理 |
| 学生反馈 | 为单个学生编写、预览和发布评语，保存内部观察 | 同步管理评语、结合完整报告持续跟进 |
| 个性化方案 | 查看已确认方案、执行进度与学生困难反馈 | 编写、调整、确认下发方案及安排复测 |
| 出题与批改 | 查看相关待办并保留“到网页端继续”的上下文 | 复杂出题组卷、连续批改、评分复核与最终成绩发布 |

首期建议先完成上述移动工作，不将复杂组卷、成批阅卷或最终成绩发布放入手机主流程；这属于分工提案，后续可据真实使用调整。跳转网页端须重新验证身份，链接不携带答案、学生报告或登录凭据。

建议同一微信小程序按已核验身份提供教师/学生工作区；切换工作区只改变入口，不增加权限。共用或独立 AppID、部署和认证接入仍是技术决策，本文不提前确定。学校确认教师身份与任教关系，用户不能通过选择“我是教师”自行获得教师权限。

## 2. 信息架构与 12 个页面

底部导航为 **工作台 / 学情 / 评语 / 我的**。顶部持续显示当前学校、学期、班级与学科；切换范围时重新加载授权数据，保留尚未提交的草稿所属范围。无任教关系时仍可访问个人资料，但不能打开班级学情或向学生发布评语。

| ID | 页面与入口 | 核心内容和动作 | 阶段 |
| --- | --- | --- | --- |
| TM01 | 登录与教师身份 | 微信绑定、学校核验、任教范围、账号帮助、有效身份切换 | M1 基础，M3 移动入口 |
| TM02 | 工作台 | 当前待办、近期任务、待跟进学生、教学随记入口 | M3 |
| TM03 | 任务详情与提交进度 | 要求、分配人数、未开始/作答中/已交卷/待批改、异常与困难反馈、按学生催办 | M3 |
| TM04 | 教学资料查阅 | 本人资料及获授权共享资料、版本、预览、权限与索引状态 | M1 基础，M3 移动入口 |
| TM05 | 教学随记 | 简短教学反思、学科和教材标签、私有草稿保存 | M3 |
| TM06 | 班级学情概览 | 提交/评分覆盖、已确认成绩摘要、需跟进学生；知识点分布后续接入 | M3 基础，M4 掌握度 |
| TM07 | 学生学科详情 | 本学科成绩、时间范围、有效证据、评语入口及方案入口 | M3 基础，M4 掌握度 |
| TM08 | 知识点与证据详情 | 题目和评分依据、独立题数、最近时间、有效性及修订状态 | M4 |
| TM09 | 评语中心 | 草稿、待开放、已发布、已撤回；按学生、类型和任务筛选 | M3 |
| TM10 | 评语编辑与发布预览 | 明确接收学生、日常/任务/阶段类型、关联背景、正文、证据与发布确认 | M3 |
| TM11 | 教学方案与执行 | 教师已确认方案、学生任务、完成/受阻/待复测、困难反馈处理记录 | M4 |
| TM12 | 我的 | 任教信息、学校切换、个人资料入口、通知、隐私、设备退出及账号支持 | M1 基础，M3 移动入口 |

页面 ID 是设计引用，不表示已有路由。M1 建立身份与权限基础，M3 交付教师移动待办、进度、评语及基础成绩，M4 补充掌握度和方案查看；完整首期必须覆盖 M1–M4。

## 3. 简单工作的具体流程

工作台首先展示当前范围内待跟进任务和学生困难反馈；待审核、待批改可查看数量与详情，再到网页端继续。筛选学科后保留其他学科待办提示，不把不同学科成绩混成综合能力分。

TM03 按分配、开始、交卷和批改事实统计，缺考、未提交、已提交待批改分别呈现。提交进度不等于成绩；移动端不能为了清除待办擅自把未批改题记为零分。任务名单或任教关系变化后，打开学生记录时重新验证权限。

教师可为尚未完成任务的指定学生发送任务提醒，先预览接收对象和任务，再确认催办；发送时重新验证有效任教关系与任务分配范围。按任务、学生和同一次操作去重并限制频率，失败重试不重复提醒；站内提醒独立可查看，微信通知是否送达单独记录，通知不展示成绩或薄弱项。

TM04 沿用个人知识库和学校共享边界：本人可检索不表示已共享，学校成员身份不开放他人私有资料。授权撤回后刷新预览和缓存状态，不能从旧消息链接继续获取已受限的正文、附件或来源。

TM05 适合随手记录本次课堂有效的方法和待调整的讲解，默认存入教师个人库，不自动共享。涉及可识别学生的观察记录放入独立教学记录；向学生发送反馈须单独进入 TM10，不能把随记或内部观察直接当作已发布评语。

## 4. 手机上的数据分析

TM06 先回答“哪些任务尚未完成评分、哪些学生需要跟进”，再展示同一测评范围内的成绩概览。摘要注明任务、学科、时间范围、有效人数、缺考/待批改人数和最近更新时间；不同满分、范围或难度不可直接拼接成涨跌结论。

TM07 支持从班级进入单个学生本学科记录，先看已确认结果，再看知识点和教学动作。临时批改进度与正式成绩分别显示；存在待批改时不展示伪完整总分，不将尚未评分的题目纳入掌握度估计。

M4 的掌握度必须伴随独立题数、最近测评时间和覆盖范围；“未测评”“证据不足”“需要巩固”“达到当前目标”使用文字区分。阅读完成、同题多次重练不充当多个独立测评证据。

从 TM07 到 TM08 可查看具体作答、评分与知识点映射；无效题、复核和重算中的结果有明确状态。图表提供简短文字摘要与可展开明细，不能只有颜色或百分比；教师查看的未开放结果不会因截图式分享或评语引用自动转给学生。

TM11 展示当前已确认方案版本、下一步安排、执行和复测状态。教师可查看学生的“看不懂”“时间不足”“材料打不开”等反馈并记录跟进；涉及修改任务、目标或最终结束方案时，首期建议转网页端完成正式确认。

## 5. 学生评语：写得快、对象清楚、发布可控

评语是教师向某个学生提供的教学反馈，区分日常评语、关联任务评语和阶段评语；内部课堂观察是另一种默认仅记录教师本人可见的记录，不能通过切换标签自动变成学生消息。首期建议以单个学生为发布单位，批量评语作为后续增强。

1. 从 TM07、TM03 或 TM09 进入 TM10，固定并显示学生、学校、班级、学科及相关任务/周期；搜索同名学生时同时显示班级等必要识别信息。
2. 选择评语类型，描述具体表现、依据和下一步建议。默认保存草稿，不能输入即发送；从数据页带入的内容需由教师核对。
3. 如引用测评，必须关联对应测评及证据。预览明确区分学生最终可见内容、内部观察和当前不可开放的信息，不把教师私有资料或未开放答案夹入正文、附件及通知摘要。
4. 发布前再次显示接收学生、背景、正文与开放时间/条件，由教师明确确认。任教或在班关系失效、对象变化、证据状态变化时阻止继续并提示重新核对。
5. 服务端确认后显示评语版本与实际状态；学生通过 S17 教师评语详情阅读，任务相关入口位于 S07，方案上下文可从 S14 到达，消息入口位于 S16。
6. 教师在 TM09 查看已发布、待开放及学生已读状态，学生打开详情才计已读；提交发布成功、站内可访问、通知送达、已读是不同事实，不声称通知失败代表发布失败。

所有测评关联的任务评语正文及其证据入口须随对应测评进入“完整讲评”后向学生开放，不能在仅成绩阶段通过评语提前显示。这不改变学生成长概览的规则：掌握度概览最早随相应成绩开放，逐题依据仍需完整讲评。日常和阶段评语可独立发布，但包含尚未开放的成绩、作答、知识点判断等信息时，必须绑定相应测评，并受其开放规则约束；无法确认依据时保留草稿，不通过改名或摘要绕过限制。

完整首期之后可提供可选的 AI 评语草稿，依据获授权学习证据提出具体建议，教师编辑、核对并确认后才能发布。不得自动群发，不生成“懒惰”“能力差”等人格或能力定性，不把 AI 猜测当作教师观察事实。首期的手工评语无需依赖 AI 才能使用。

已发布评语更正须留下版本、原因和操作者，学生看到更正提示；撤回停止后续读取并显示相应状态，保留必要审计，不能承诺删除学生已读、截图或通知中曾出现的内容。通知正文默认只提示有教师反馈，具体内容登录后读取。

## 6. 保存、权限与跨设备协作

TM05、TM10 明示“本机暂存 / 正在同步 / 已保存至服务器及时间 / 保存失败”，发布前必须确认服务端已保存的当前版本。网络断开时保留可恢复草稿，恢复后重试；本机暂存不能被标为已发布，换设备以服务端确认版本为准。

发布超时先查询同一操作结果，重复点击或重试只生成一条评语版本；通知重试不会重发评语。网页端 T25 与 TM09/TM10 共享草稿、版本和发布状态，存在较新版本时展示差异并让教师选择合并或恢复，禁止旧端静默覆盖新内容。

个人资料与教学随记按所有者及资料授权校验，无任教关系也可使用本人私有库；涉及班级、学生、学情或评语的读取、保存及发布，再检查学校、学期、班级、学科和有效任教关系。二维码、通知和页面深链只提供定位。

切换角色或学校、退出账号前检查本机未同步草稿，先同步，或明确提示暂存风险并让用户选择处理方式；不得静默丢弃，也不能暴露给另一个角色或账号。继续保留的本机暂存须按身份隔离且在重新授权后恢复；无法继续访问的草稿说明原因。退出后清除会话和受限展示缓存，换设备以服务端确认版本为准。

## 7. 验收与试点观察

以下为拟议验收场景，本轮未实现或执行功能测试。

1. 教师绑定经学校确认，普通账号不能自选身份越权；多校、多学科切换及关系结束后，旧链接仍受服务端权限限制。
2. 从 TM02 查看任务提交进度再进入单个学生，未交卷、缺考和待批改不被误显示为零分或已完成。
3. 资料查看遵守个人私有和明确学校共享；教学随记不自动共享，内部观察不出现在学生响应或消息中。
4. 同名学生、转班学生和过期任教关系下，评语发布对象被明确核对，失效范围不能继续发送。
5. 测评隐藏、仅成绩、完整讲评三个状态下检查正文、关联证据、消息和缓存；日常/阶段评语不能泄漏未开放测评信息。
6. 评语断网保存、发布超时和重复点击均可恢复，最终只有一条有效记录；通知失败与未读分别显示。
7. 网页端 T25 与手机同时编辑同一草稿会提示版本冲突；更正、撤回保留审计并在学生 S17 呈现当前状态。
8. 学生经 S07/S14/S16 进入 S17 只能查看本人已开放评语；首期无 AI 服务时仍可手工反馈。后续接入 AI 草稿时须另验教师确认前学生不可见。
9. M4 从班级到学生再到知识点证据可追溯；证据不足、待批改、无效题和重算状态一致，不因手机摘要简化而丢失限制。
10. 在真实手机的大字号、弱网和辅助阅读场景下完成查看进度、查看学生成绩、写评语并确认发布，图表有可理解的文字说明。
11. 催办前显示指定学生和任务，重复操作受去重与频率限制；已完成任务、失效任教关系不能继续催办，通知失败不会重复生成提醒。
12. 角色切换前能发现未同步教师草稿或学生答卷；按身份隔离保留和恢复，不向新角色暴露，也不因清理展示缓存而静默丢失。

试点观察移动待办处理时长、找到学生证据所需步骤、评语草稿恢复成功率、错发/重复发布情况及学生实际打开后的理解反馈；通知授权率与已读率不代替教学效果。具体指标目标在试点基线建立后确定。
