# KnowPulse 教师端产品规划

> **历史文档／已退役（2026-11-01）**：本文记录早期学校教育方案或当时的实现与验证，学校管理、学校身份核验和旧 `/education/*` 工作区已退出当前产品。文中的“已确认”“当前”及验收结果仅指原记录时点，不作为现行需求或可用功能承诺。当前方向以[教师出题与学生答题业务需求](../business-requirements.md)及[项目改造计划](../project-refactoring-plan.md)为准：教师使用 `/teacher/*`，学生使用平级独立 `KnowPulse.MiniProgram`。

日期：2026-10-06。状态：产品方案提案，尚未实现；与[总规划](../education-product-plan.md)、[教师小程序规划](education-teacher-miniapp-experience.md)、[学生端规划](education-student-experience.md)配套阅读。

已确认方向：初中、多学科、教师知识库默认私有且可主动共享到学校，教师和学生均有微信小程序入口。教师小程序承担简单工作、学情查看和学生评语。下文中的页面、状态、操作规则与验收方式为拟议产品设计；首批学科、教材版本、试点规模和排期仍待确定。

## 1. 教师要完成的工作

教师网页端复用现有 Blazor 产品，承接资料整理、备课出卷、完整批改和方案编辑；首期同时提供教师微信小程序，用于移动待办、任务进度、基础成绩与学情查看、学生评语和课堂速记。两个入口操作同一份业务记录，页面与按钮可不同，任教权限和可见性规则一致。成功体验是教师能跨设备完成可追溯教学闭环，并把教学反思沉淀回个人知识库。

| 工作场景 | 教师要解决的问题 | 应交付的结果 |
| --- | --- | --- |
| 日常积累 | 多年教案散落，换教材后难找资料 | 可按教材、知识点和年份找到的个人教学成果 |
| 课前准备 | 当前章节需要练习，逐题寻找与改编耗时 | 有依据、已审查、适合本次教学的试卷 |
| 布置与跟进 | 多班多学科任务容易混淆 | 明确对象、时间、规则和提交状态的任务 |
| 课后批改 | 主观题不能只看最终答案 | 按评分点记录的分数、反馈与复核轨迹 |
| 学情判断 | 总分难说明下一步怎么教 | 可追溯至题目和作答的薄弱点与证据范围 |
| 个别辅导 | 报告生成后缺少实际教学动作 | 教师确认的讲解、材料、练习和复测安排 |
| 移动跟进 | 课间或外出时需要查进度、看学生情况并给反馈 | 手机上可查看学情、处理轻量待办、发布给指定学生的评语 |
| 教研复用 | 成功方法难沉淀，个人资料不想全部公开 | 可持续修订的教学反思与自主共享记录 |

## 2. 首次使用与持续使用

首次进入先创建或恢复个人知识库，再选择当前学校、学期和任教学科。学校成员及任教关系由受权人员确认；教师可查看并申请更正，不能自行选择全校任意班级获得权限。没有任教关系时仍可整理自己的资料，布置和学情功能解释缺少的条件。

入门任务按“确认任教信息 → 选择当前教材 → 上传一份资料 → 检查可检索内容 → 生成并审核一组题 → 布置给学生”递进。教材信息未齐时可先整理资料；学校共享始终是独立可选动作，不作为完成入门的条件。

工作台默认恢复上次学校、学期、学科及班级。跨学校切换时重新加载授权范围并清楚显示当前上下文；未保存的编辑先保留草稿。跨学科总览只聚合待办，不混算知识点指标。

## 3. 信息架构与页面清单

网页端一级导航建议七组：**工作台、我的知识库、教材与备课、题库与出卷、教学任务、班级与学情、教学方案**。教师小程序采用“工作台、学情、评语、我的”四个入口，具体见配套规划。学校共享放在知识库内，避免把个人库与公共库混成一份列表；AI 能力嵌入出题、解读与方案流程，不要求教师先选择模型。

T 页面编号指教师网页页面，TM 指教师小程序页面，均非已创建路由。阶段：M1 身份/班级/任教关系及私有库与基础共享；M2 教材/知识点及出题审题组卷；M3 师生小程序、学生评语、考试学习、人工批改与证据；M4 掌握度分析、教师确认方案与复测。四阶段共同构成完整首期。

消息中心与个人设置为全局入口，不新增一级菜单；学校管理、系统模型配置与企业组织管理只对相应管理角色开放，不置于普通教师的日常导航。

备课记录作为 T07 章节内的任务聚合视图，记录本次教学目标、选用资料、关联题目/试卷和课后反思，并能从 T04 回到相关备课记录。教师可从历史记录复用目标与资料选择、再核对当前教材；课后反思沉淀为本人资料，不复制学生个人学情到共享知识库。首期无需为备课另设独立复杂编辑器。

### 网页与教师小程序的协同

手机端保存的资料灵感、教师观察和评语草稿在网页端继续编辑，手机端查看与网页相同范围、同一版本的学生报告和任务状态。手机端复杂题目编辑、正式评分修订和深度方案调整首期交由网页端，保留当前记录及继续处理入口。

两端同时编辑时检测版本差异并允许保留草稿，不以最后一次保存静默覆盖。切换学校、班级或学生后重新校验对象；网络恢复时先同步最新状态再允许发布评语，离线不能显示发布成功。授权失效时保留个人未发布内容，但停止对原班级学生的进一步读写。

## 4. 六条关键流程

### F1：积累私有资料，再决定是否共享

1. T03 录入资料或上传附件，默认显示“仅自己可见”，选择学科与资料类型；保存后可离开，保留成功附件和草稿。
2. T04 明确区分“已保存”“处理中”“可用于检索”“仅附件”。只有已通过完整索引的内容才能作为可检索依据；解析有误时可补正文、修订或重试。
3. 教师在 T06 检查检索结果和引用，再将其用于备课或出题；本人可检索不意味着学校可见。
4. 如需共享，T05 展示资料标题、具体版本和学校范围，经教师确认后开放。后续个人修订不会自动替换已共享版本。
5. 撤回时展示受影响的共享入口；成功后阻断他人的新检索、下载与新出题使用。D03 已确认：此前已布置给学生的材料也停止后续在线正文/附件读取，保留历史答卷和已上交记录按各自权限追溯；记录不重新授予原资料阅读权。既有冻结考试及成绩规则独立适用，不声称撤回能收回他人已看过或下载的副本，见 ADR 0029。
6. 年度整理以归档保留版本和关系；删除影响、离校资料迁移与历史试卷使用政策在执行前明确，不用“退出学校”暗示个人库自动删除。

### F2：按当下教材生成题目，并由教师审核

1. T07 选定本学期真实使用的教材，T08 确认章节与知识点；“当前”由教师确认，系统不能按文件上传日期猜测。
2. T09 明示可用资料范围。默认本人资料，可明确加入已授权的学校共享资料；改变教材后复核原有选择。
3. 提交题型、数量、难度与分值后，可离开并回到同一任务。材料不足时列出缺少章节或知识点，支持减少题量、补材料或人工录题，不强行补齐。
4. T10 逐题对照原文依据与教材适用范围；AI 推荐的知识点、答案与评分要点需要教师确认。重新生成保留旧候选对照，不能覆盖教师已编辑内容。
5. T11 对客观题检查答案结构，对填空题检查空位顺序与可接受答案，对主观题检查评分点及文本/图片作答要求。审核通过才进入 T12。
6. T13 调整题序、分值与覆盖，在教师视角核对答案，在学生视角核对公式、图片与作答控件；任何未审题阻断正式发布。

### F3：把一份试卷布置给正确学生

1. 从 T13 进入 T14，选择“练习”或“测评”；本期仅列出本人有效任教范围中的班级和学生，显示最终人数与学科。
2. 设置开始/截止时间、时长、次数、补交处理及“隐藏/仅成绩/完整讲评”三个开放层级；成绩与完整讲评的开放时间独立配置，答案与解析在完整讲评时一同开放，错题收藏另行授权。拟议默认：正式测评完成批改后按任务统一发布最终成绩，结束且教师确认后开放完整讲评。
3. 发布前检查未审核题、总分、时间冲突、主观题评分要求、学生材料访问范围和最终名单；名单变更时要求重新核对，不悄悄扩大接收人。
4. 发布成功固定任务、试卷、题目、评分规则及接收人记录；学生在小程序看到新任务。通知失败不改变任务已发布事实，教师可查看站内送达状态并重试通知。
5. T15 跟进任务进度。尚未开考的时间或名单变更须再次确认并提示受影响学生；已开始后不直接改题，错题纠正通过说明、作废题与评分修订流程处理。
6. 截止后显示服务端接收结果；缺考、已提交待批改、异常提交分开统计。重新布置或补测形成独立记录，不能覆盖第一次测评。

### F4：人工批改后，依据证据分析学生

1. T16 支持按题连续批改与按学生整卷查看；主观题首期采用文本/图片作答和人工评分，图片可放大，保留原稿；OCR 和 AI 自动判分不作为先决条件。
2. 客观题结果与主观题待评分分开显示。评分草稿可保存；确认时校验分数范围、必需评分点和反馈，未确认主观题不计为零分。
3. T17 提示还有多少题/学生未批改。拟议首期在提交窗口结束、进行中答卷封存且有效提交集合固定后，整项任务完成批改再统一发布最终成绩；缺考、取消和正式豁免分别记录。学生待批改期间不看到临时客观题分或部分成绩，不把未评分题算为零分。仍有人可开始、继续或追加尝试时不得开放完整讲评。
4. 发布后学生按“隐藏/仅成绩/完整讲评”获得相应内容；答案和解析在完整讲评时一起开放，收藏错题仍需对应授权。复核必须填写原因，保留原分数和新分数；重新计算学情，显示更新时间，避免旧报告继续被当作最新事实。
5. T19 从知识点汇总进入 T20，核对独立题数、最近测评时间、评分点与题目权重。多个知识点不重复分摊整道题的全部分数。
6. 同分学生可呈现不同薄弱点；未测评、证据不足与有薄弱信号分别表达。AI 解释引用已有证据，不把“粗心”“不努力”当作由分数推断出的事实。

### F5：形成教学方案，并用复测修订

1. 从 T19 选择需要干预的知识点和证据区间进入 T21；证据不足时先建议补充诊断，不直接生成确定性结论。
2. 方案草稿同时包含“老师怎么教”和“学生怎么学”：教学目标、讲解建议、例题、学习材料、练习顺序、执行周期、复测与达标条件。
3. 教师检查材料访问权和负担，调整任务，记录需要的课堂观察；确认后才下发。学生只收到学生任务与适宜反馈，不接收内部诊断备注或教师私有题源。
4. T22 区分已安排、学习活动完成和测评达标；教师可记录观察。阅读完成只更新活动状态，不直接提高知识点掌握度。
5. 用于更新独立测评证据与完成教学闭环的复测须使用相同知识点的新题，并保留与原方案的关系；原题可复练但单列。首答、原题订正和新题复测分别展示，不用重复作答放大独立证据量。
6. 展示前后证据、覆盖变化与未完成活动，由教师决定继续、调整或结束。可把不含可识别学生信息的教学方法与反思整理回 T04，再独立决定是否共享。

### F6：在手机或网页查看学生情况并写评语

1. 在有效任教的班级/学科中选定学生，查看成绩、任务完成情况及证据时间。成绩尚未完整或正在重算时标明范围，不能根据缺失数据写确定结论。
2. T25 或教师小程序选择日常、任务或阶段评语；先保存草稿。教师观察默认为作者本人可见，转为评语时选择要公开的内容，不能把全部内部笔记自动带入。
3. 教师可使用常用语并作个性化修改；AI 评语建议作为完整首期之后的可选增强，需核对事实后确认。发布前预览学生、班级、学科、关联任务、正文和开放规则，首期逐人处理，批量个性化发送后置。
4. 测评任务评语随完整讲评开放；其他评语如引用未开放测评，同样绑定该测评等待开放。对学生的评语不含他人成绩、未开放答案或教师私有题源。
5. 学生从 S17 阅读已发布内容，教师分别看到已发布与已读状态；发布重试不产生重复评语。更正和撤回保留版本、作者及原因，不能承诺消除学生已经读到的内容。

## 5. 页面状态、效率与可访问性

| 情况 | 应有体验 | 避免的误导 |
| --- | --- | --- |
| 异步上传、索引或生成 | 明示当前阶段、已完成结果、可离开、返回入口与失败修复动作 | 用旋转图标无限等待；把上传完成当作可出题 |
| 空状态 | 区分从未创建、筛选无结果、尚无授权；给一个相关下一步 | 全部显示“暂无数据” |
| 权限改变 | 保留已存草稿，告知当前操作不可继续；刷新有效班级/资料范围 | 因曾打开页面就继续允许写入 |
| 弱网与重复点击 | 显示保存中、已保存时间、失败重试；同一发布结果可恢复查询 | 未确认保存就显示成功；重试生成重复任务 |
| 多人或多标签修改 | 提示较新版本，允许对照与恢复本人内容 | 静默覆盖评分、题目或发布设置 |
| 批改效率 | 保留当前题/学生和筛选位置，提供键盘导航与可撤销草稿操作 | 分数一输入即不可逆发布 |
| 学科内容 | 长题干分段、公式可读、图片放大与描述、音视频范围明确 | 缩小图片当作支持了公式和图表 |
| 键盘与读屏 | 字段有标签，错误关联到字段，焦点跟随弹层与结果，状态用文字表达 | 只用红绿表示对错、仅悬浮可查看依据 |
| 大字号与小屏 | 主任务可完成，图表提供表格明细，宽表可定位行列 | 报告只有彩色图而无法核对原始值 |

批量操作先显示选中数量与影响范围；共享、布置、成绩发布的确认页始终重复显示“谁将看到什么”。这些确认属于实际产品操作设计，不是产品规划文档的审批要求。

## 6. 权限范围与教师可见信息

| 对象 | 教师可做 | 首期禁止的默认扩权 |
| --- | --- | --- |
| 本人知识库 | 维护、私有检索、出题、导出，主动共享选定版本 | 学校成员自动读取；管理员日常浏览全部私有资料 |
| 学校共享资料 | 在仍有效的授权范围内阅读与复用 | 将原作者个人库整体开放；撤回后继续新建衍生任务 |
| 班级及学生 | 在有效学校/学期/班级/学科任教关系内布置与分析 | 凭教师角色查看全校或其他学科的详细作答 |
| 学生教学记录 | 查看本人承担教学职责所需的提交、评分、报告、方案反馈 | 将个体学情默认收入学校共享 RAG |
| 学生私有笔记 | 仅查看学生主动作为任务提交或明确授权的内容 | 把学生个人知识库当作教师监控空间 |
| 成绩与评分 | 在授权任务内批改、复核和发布，保留变更 | 不留记录地覆盖既有评分或改写历史题目 |
| 学生评语与教师观察 | 本人任教范围内写评语，对本人发布内容更正；个人观察保持私有 | 手机入口绕过网页权限；把内部记录公开；借评语提前开放答案 |
| 转班/离校后记录 | 依据单独明确的留存及交接政策展示必要历史 | 自动延续旧任教权限，或直接删除个人所有资料 |

列表、搜索、附件、导出、报告、AI 引用和任务操作使用同一业务范围；页面隐藏按钮不能代替服务端验证。校内共备、协同批改和跨学科联合分析可扩展，但首期不假定已获得额外授权。

## 7. 通知与学生端交接

教师站内通知覆盖索引失败、出题完成、待审核、提交截止、待批改、分数复核、方案待评估；成功和无变化状态合并，避免每位学生每次保存都打扰教师。可设置普通提醒偏好，关键失败保持可查。邮件、短信及微信主动消息仅在相应渠道已具备条件并获得用户选择后规划，不作为首期闭环成立的依赖。

| 触点 | 教师确认的事实 | 学生得到的内容 | 回流到教师的信号 |
| --- | --- | --- | --- |
| T14/T15 → S03–S06 任务发布 | 固定版本、名单、时间、次数与开放规则 | 本人任务、作答须知、可访问试题 | 是否开始、保存确认、唯一提交结果 |
| T14/T15 → S09 学习材料下发 | 明确版本及任务范围授权 | 指定材料及学习要求 | 完成活动、配套练习、学习反馈 |
| T16/T17 → S07/S10 评分与成绩发布 | 全任务评分已确认，成绩与完整讲评开放时间已设定 | 三层级裁剪后的结果；完整讲评含答案与解析，错题收藏另行授权 | 查阅情况、拟议复核申请及处理状态 |
| T21/T22 → S14/S15 个性化方案下发 | 教师确认的目标、任务、期限与复测 | 学生可执行的任务和目标说明 | 完成度、困难反馈、复测提交 |
| T25/教师小程序 → S17 学生评语 | 收件学生、正文、背景、版本及开放条件 | 对本人已开放的评语与更正提示 | 对应版本实际打开后的已读，非通知发送状态 |
| 修订/撤销 | 变更原因、影响范围、有效新版本 | 变更提示与明确下一步 | 新规则下的任务执行，不覆盖旧记录 |

双方统一以服务端时间和已保存记录为准；教师不能把“消息已发出”当作学生已阅读，也不能把学生暂时离线当作缺考。学生端不获得题库管理返回值、隐藏答案字段、私有题源或教师内部备注。

## 8. 阶段验收与设计验证

| 阶段 | 教师侧验收场景 | 成立条件 |
| --- | --- | --- |
| M1 | 两位同校教师分别上传，本人检索；共享一份再撤回 | 未共享资料互不可见；权限变化覆盖附件、引用和检索；无任教也能整理个人库 |
| M2 | 在至少两门已选学科按各自教材生成、人工修订、审核组卷 | 不混教材与同名知识点；不足能解释；未审题不能发布；学生预览表达正确 |
| M3 | 为真实试点班级发布含客观题和已选主观题的任务，完成批改发布 | 学生范围正确；文本/图片可阅；待评分不算零；重复提交不产生重复成绩 |
| M3 移动教师 | 手机上查任务和基础成绩、写评语，网页继续修改并发布给学生 | 范围与版本一致；未公开草稿和观察不泄漏；断网重试不重复发布 |
| M4 | 从薄弱点查到原题并下发方案，学生学习和新题复测，教师评估 | 每项判断可追溯；材料授权正确；阅读不等于掌握；复测后可调整或结束 |

发布前用角色任务走查验证：新教师首次导入、熟练教师批量出题、多班教师发布、主观题集中批改、证据不足的学生辅导，以及手机查学情和跨端评语编辑。记录完成率、耗时、错误原因和中断恢复情况；观察结果用于定指标，不虚构已验证的效率收益。

当前可复用的界面基础包括[知识管理](../../src/KnowPulse.Blazor.Client/Pages/Knowledge/Management.razor)、[题库工作台](../../src/KnowPulse.Blazor.Client/Pages/QuestionBank/QuestionBankWorkbench.razor)、[考试管理](../../src/KnowPulse.Blazor.Client/Pages/Exam/Management.razor)及[我的学习](../../src/KnowPulse.Blazor.Client/Pages/Learning/MyLearning.razor)。现有考试界面仍使用全员/部门/岗位/指定用户分配，不等于教育任教范围；题库已有候选、草稿、审核和正式题流程，但本规划中的教材版本、教师私有归属、学情和方案页面仍需新增或扩展。

本方案沿用[ADR 0007](../adr/0007-private-personal-knowledge-with-explicit-school-sharing.md)的私有归属与显式学校共享；未新增不同于现有 ADR 的架构决定。离校策略、历史快照复用与正式测评的特殊发布规则，应在对应阶段形成明确决策后再实现。
