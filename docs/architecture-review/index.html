结论先读

项目适合继续采用 ABP 分层单体。PostgreSQL 保存事实、Blob 保存原件、Qdrant 保存可重建索引的职责划分清楚；教育路径已经具备冻结答卷、评分修订、统一成绩发布和教师确认方案的完整数据模型。没有证据支持现在拆成微服务或引入新的通用工作流平台。

优先处理审计报告的 1–4 项：旧考试答案覆盖、旧考试超时恢复、旧向量挤占召回、索引长事务。它们不等同于“教育闭环全部失效”；旧企业考试与教育测评必须分别评估。

本轮只新增审查文档和图，并同步已确认的账号支持决策文字。没有修复业务代码，没有应用迁移，没有提交或部署。

全仓库审计报告

What this repo does: KnowPulse 管理企业和教师的知识资料、检索问答、题库、考试与学习。教育模块进一步支持学校关系、师生微信工作区、冻结测评、学情证据和教师确认的教学方案。按共享 PostgreSQL、多个师生同时使用的学校场景审查；生产容量未给定，不虚构承载人数。

本报告只列能落到输入或执行路径的问题，共 8 项。1、2 有本轮纯领域代码探针；3、4、5、6 是源码路径结论，其中 4 另外核对了当前 ABP 版本的事务规则；7 是可复现的脚本失败；8 是测试边界缺口。没有把已记录的规模限制、尚未确认的产品政策和推测性安全问题当成缺陷。

Must fix · 优先修复

1. 旧考试会用迟到的答案覆盖较新的答案

  • What this is: 企业旧考试的 ExamAnswer.Save 接收答案内容和客户端版本。入口为 ExamAppService.SaveAnswersAsync，规则在 ExamAnswer.cs。
  • Problem: 已保存版本 2 的答案 B，另一设备迟到地提交版本 1 的答案 A；代码接受 A 并将其升为版本 3。本轮实际调用领域对象复现，旧版本没有被当成冲突。
  • Fix: 按现有客户端协议拒绝低于或等于当前版本的非重复请求；同一操作标识仅在内容一致时返回旧回执。检查 Web 调用方的版本含义后同步修正，并增加一个双设备乱序保存用例。
  • If we skip it: 网络乱序或换设备后会静默丢失较新的作答。教育专用响应修订使用另一套版本检查，不可因该路径较完善而忽略仍可访问的企业旧入口。

2. 旧考试超时后仍恢复同一份不可编辑的答卷

  • What this is: StartAttemptAsync 优先返回任一 InProgress 答卷；ExamAttempt 控制作答时限。
  • Problem: 计划还开放且允许两次尝试时，第一次答卷已经超时，恢复入口仍返回它。保存只抛异常而不改变状态；提交先设 Expired 再抛异常，正常事务回滚后不会持久化这个变化；当前后台截止任务只处理教育答卷。
  • Fix: 在同一事务内先结束已经超时的旧答卷，再判断剩余次数并返回或创建有效尝试。不要依赖抛出异常前的状态赋值完成持久化；保留已经保存的答案。
  • If we skip it: 用户进入“能恢复、不能保存或提交、也不能开始下一次”的死路。本轮探针确认超时保存被拒后对象仍为 InProgress，数据库回滚部分为源码与事务规则推导，未做真实 PostgreSQL 复现。

3. 重建知识索引后，过期向量可能挤掉有效检索结果

  • What this is: 摄取管道 重建时停用旧分块并生成新分块 ID；Qdrant 适配 以分块 ID upsert。
  • Problem: 停用只写主库，旧向量仍保留原来的已发布 payload。全树查找 DeleteByKnowledgeVersionAsync 只有定义和测试，没有生产调用；检索器 只取最多 100、通常为 TopK 三倍的候选，复核后不补召回。若前 15 个都是同一文档历次重建留下的高分旧块，TopK=5 可以返回空，即使有效新块排在第 16 位。
  • Fix: 在重建完成后按确切旧分块 ID 清理或停用旧向量，保留可重试的清理事实；或把当前有效索引代次加入候选过滤。不能直接无条件调用“删整个版本”，那会误删并发产生的新向量。
  • If we skip it: 索引显示成功，但重建次数越多越可能查不到内容，向量存储也持续膨胀。数据库复核仍阻止旧正文泄漏，这项首先是检索正确性和清理问题。

4. 知识索引把外部转换和模型调用包在一笔长事务里

  • What this is: KnowledgeIndexJobProcessor.ProcessAsync 带普通 [UnitOfWork]，内部依次调用摄取、Embedding 和 Qdrant。进度写入使用 autoSave: true。
  • Problem: 在当前默认事务配置下，ProcessAsync 的事务到整个方法结束才提交。假如模型调用耗时 60 秒，其他连接不能看到中途已 flush 的心跳，且已更新行的锁持续存在；autoSave 不是事务提交。ABP 10.6.0 拦截器 和 默认选项 支持这一判断。
  • Fix: 参考已有 AI 出题处理器，用短事务认领、独立心跳、事务外外部调用、带执行编号复核的短事务完成。必须同时保留过期执行者的防回写检查，不能仅关闭事务或给心跳另开事务却继续持有外层锁。
  • If we skip it: 进度和卡住检测失真，慢模型拖住数据库事务，恢复操作可能等待锁。当前 SQLite 测试主动关闭事务，因此“管道通过测试”不能证明该场景正常。

Should fix · 随后修复

5. 日志分页会先读取和授权检查全部历史记录

  • What this is: RagCallLogAppService.GetListAsync 提供带来源校验的分页日志。
  • Problem: 代码先载入过滤后的全部日志和全部引用，再逐引用调用来源授权，最后才 Skip/Take。一个用户积累 10,000 条、每条 5 个引用时，打开第一页也会走至多 50,000 次来源校验，而不是只处理这一页；这是操作次数推导，不是本轮压测数据。
  • Fix: 将可表达的归属及来源授权合入 SQL，再对当前页批量读取引用。若先采用分批扫描，必须明确总数语义，不能把扫描上限当成真实总数，也不能把授权校验移到分页之后。
  • If we skip it: 审计页延迟和内存随历史增长，同一数据库还会承担教学请求。该问题没有使用项目已接受的检索规模 shortcut 作为依据。

6. 每个模型请求都新建并释放 HTTP 连接池

  • What this is: Embedding 客户端 与 Chat 客户端 在每次调用中 new HttpClient。
  • Problem: 一个文档分成 200 块时，Embedding 循环会创建 200 个独立客户端，无法复用前一请求的连接池；同时问答和出题继续重复这一行为。存在确定的连接复用损失，但本轮没有测出连接耗尽阈值。
  • Fix: 使用现有 .NET DI 的 IHttpClientFactory 或由 DI 管理的客户端；认证头仍按请求设置。保留超时与受控错误信息，不引入新的网络框架。
  • If we skip it: 额外握手和短连接增加延迟、网关压力及端口占用，真实吞吐上限更难预测。

7. Provider 边界检查与已批准的 ADR 冲突

  • What this is: verify-rag-provider-boundaries.ps1 全面禁止 DataIngestion 引用；ADR 0003 已批准隔离在适配器内的 MarkItDown。
  • Problem: 本轮运行脚本实际失败，命中合法的转换器和 Application 包引用。检查无法区分“批准的适配实现”和“类型泄漏到契约或领域”。
  • Fix: 只对确切批准的文件与包设窄例外，继续检查 Contracts、Domain 和 UI 不得引用这些 provider 类型，并保留违规样本验证。
  • If we skip it: 开发者会反复遇到假失败，或逐渐跳过整个边界检查，失去它原本应有的保护。

8. 默认集成测试无法验证事务回滚与真实写竞争

  • What this is: EF 测试模块 使用内存 SQLite，并调用 AddAlwaysDisableUnitOfWorkTransaction。
  • Problem: 发布、学校授权屏障、封存和评分替换都依赖事务；默认测试无法在“写入第一张表后抛异常”时证明前面的写入回滚。本轮没有找到纳入常规测试入口的 PostgreSQL 事务回归套件；历史手工验收日志不能持续守住这一点。
  • Fix: 保留现有快速测试，增加一个很小的 PostgreSQL 专项：发布中途失败回滚、同一学生并发保存或封存、改分和结果指针原子替换。独立测试库运行，不把全量业务测试搬到真实库。
  • If we skip it: 测试通过仍可能漏掉生产数据库上的原子性和锁问题。该项不是要求增加大量测试，而是补当前测试机制无法表达的边界。

已检查而没有认定为缺陷的设计

  • 个人知识库的所有者约束不会被历史企业知识“空范围可见”规则覆盖；学校共享使用指定版本、用途和当前关系复核。
  • 教育正式成绩来自不可变提交与已确认评分，不直接暴露老师当前评分草稿；隐藏、仅分数、完整讲评使用不同投影。
  • 已经失效的共享向量仍存在，不等于能够越权读取；主库二次校验是独立防线。
  • 学校级写屏障有并发成本，但承担关系撤销与业务写入的一致性；未取得负载证据前不建议直接移除。
  • 按进程限流、个人正文 Contains、受限共享集合展开等已有明确 shortcut；未因假设的大规模负载将其升格为确定缺陷。
  • 领域接口隔离外部供应商有实际用途，不因只有一个生产实现就建议删除；两套考试仍有独立调用方，不能直接删旧系统。

Verdict: 分层与教育业务边界可继续使用；先修 1–4，再处理查询、连接复用和持续验证。没有认定可以安全删除的生产依赖，不编造“可省多少行”的数字。

Not checked: 没有运行生产环境、真实微信、真实模型、压力或安全渗透测试；没有逐行读完全部源码、49 次历史迁移、所有 UI 和第三方实现；没有执行真实数据库迁移或旧库升级。具体覆盖见来源与覆盖范围。

技术架构：当前实现

1. 系统定位和边界

KnowPulse 是一个 ABP 分层单体：业务模块共享部署单元和关系型数据库，代码在多个 .NET 项目中分层。多个 .csproj 不意味着多个微服务。运行时至少有 API Host、Blazor Web 主机、DbMigrator 三类进程；后台消费者寄宿于 API Host。

产品包含两个相邻领域：企业知识／学习／考试，以及围绕教师个人资料、学校关系和学生学习的教育业务。教育复用身份、存储、题库、冻结试卷和模型适配，但使用独立的正式测评、评分、结果、学情和方案事实。

3. 分层和依赖规则

  1. Domain.Shared 保存跨层共用的枚举、错误码、常量和本地化。部分纯业务值规则在这里供客户端和服务端共同使用。
  2. Domain 保存实体、状态迁移、不可变值和访问判断。它不依赖 Application 或 EF Core；涉及数据库的条件由应用层加载后交给领域规则。
  3. Application.Contracts 保存服务接口、DTO、参数验证、功能权限和部分传输配置，不传 EF 或供应商对象。
  4. Application 编排授权、仓储、领域操作、事务和外部适配。复杂教育用例使用明确新事务、请求指纹及回执恢复。
  5. EntityFrameworkCore 保存一个主 DbContext、模块映射、索引／检查／外键、迁移及少量自定义仓储。
  6. HttpApi 提供显式控制器；Host 同时注册 ABP 常规控制器，很多 IApplicationService 通过 /api/app/... 暴露。仅数控制器文件会漏掉大量 API。
  7. HttpApi.Client 注册 ABP 动态 HTTP 代理；Web 通过契约和代理调用，不直接引用业务实现或 EF。
  8. HttpApi.Host 组合 Application、EF 和 HttpApi；配置身份、审计、Blob、CORS、worker 和中间件。

这种布局已经足够隔离供应商。新增业务优先延续现有模块和规则；拆出服务应以独立扩缩容、故障域或组织边界为依据，不能由文件长度决定。

学校关系 当前是否属于该学校，任教／在班／学期是否有效 EducationAssessmentAccessGuard、学校服务
版本与用途 读取的是哪个版本，是否允许检索、出题、下载、布置 SchoolKnowledgeShare、KnowledgeSourceAccessGuard
当前开放状态 此刻能否看成绩、答案、反馈或执行活动 结果发布投影、方案执行与材料读取服务

前端按钮隐藏只改善体验，不能替代上述检查。平台功能管理员不自动拥有全校学生数据或教师私有观察；学校 Manager 也不会取得个人库所有权。

普通企业知识保留历史的空访问范围兼容规则。个人资料先检查明确库归属和 owner，因此不会因空范围变成公开。将来迁移旧资料归属时必须保留这一差异。

5. 四类状态必须分开

  • 正文版本与对外发布：草稿保存不等于发布，后续私人编辑不改变已共享的指定版本。
  • 执行状态与内容状态：教学方案可以暂停，但原正式考试计时不因此重置；换正文版本也不自动恢复执行。
  • 业务事实与派生结果：原答卷、确认评分是事实；学情快照、向量是可重建派生物。
  • 消息与真实行为：收到提醒、读消息、打开正文、开始任务、上交、掌握知识点分别记录，不能用消息已读代替学习完成。

设计上的成本是实体、修订和请求参数较多；收益是能够解释历史、避免改分覆盖和丢响应后的重复操作。应通过模块接口与文档减轻理解成本，而不是把历史事实合回一张可随意修改的表。

6. 存储与事务边界

PostgreSQL 是唯一业务事实源。知识发布的策略、版本指针和待索引任务在同一事务；教育发布、固定名单、答卷封存、评分确认和当前成绩指针分别具有明确事务边界。

Blob 不加入关系型事务。上传可能先成功、后续数据库提交失败；系统优先保留可恢复草稿或不可访问的孤儿文件，不能反过来先删文件再期待数据库一定提交。导出任务有独立运行编号、过期、取消和清理追踪。

Qdrant 不加入 PostgreSQL 事务。检索回到主库核对分块、发布版本和访问范围；学校共享路径额外要求所属任务为 Indexed，当前发布版本的直接访问路径没有相同的任务状态检查，不能把两条路径写成统一的完成状态屏障。对向量写入成功、主库未提交的情况不能声称跨系统原子提交；清理和重建仍有审计报告第 3、4 项需要完善。

模型请求 有外部费用且不能数据库回滚。AI 出题和 AI 方案采用后台任务、执行编号、心跳和明确采用；不能把“自动重试 HTTP”当成安全的业务重试。

7. 租户、学校和账号

租户是 ABP 的隔离上下文；学校是租户内的业务实体，二者不是一一对应。一个账号可以在同租户的多个学校拥有不同的有效身份，个人库仍归该账号。邀请只增加经确认的学校身份，不自动增加任教、在班、功能权限或资产归属。

当前多类 worker 通过共享库取消租户过滤发现任务，再切回任务租户执行。禁用行过滤不能发现另一个数据库中的任务；若将来启用每租户独立数据库，任务发现和无租户绑定查询需要相应设计。这是部署边界，并非当前共享库配置下的缺陷。

2026-10-18 已确认账号支持采用“本人验证原账号后自助处理；无法验证时平台人工复核”。学校不接管原账号或个人资料。当前已有自助帮助、密码找回入口及本人微信解绑；异常申请和平台复核执行仍未实现。

8. 保留与改进

保留分层单体、项目自有外部接口、固定版本、短事务任务和服务端二次授权。首先把旧考试和知识索引的薄弱路径补到已有教育路径的可靠性水平，再处理分页成本与连接复用。

暂不引入微服务、消息中间件、通用工作流引擎或统一“大基类”。若需要抽取公共代码，应先证明重复处拥有同一业务规则和失败语义；相似的 DTO 或状态枚举不够。

主要依据：Host、Application 组合、Web 主机、领域词汇表、ADR 目录。

数据关系与核心流程

1. 数据模型的阅读方法

主 DbContext 声明 151 个 DbSet，包含 ABP 模块实体；这不是完整 SQL 表总数，导航实体与扩展配置也参与模型。当前有 49 个迁移文件，另有对应 Designer 与模型快照。下面画的是关键业务关系，省略审计列、租户列、并发戳及大量从表；它不是由数据库反向生成的完整物理 ERD。

所有权、当前指针和历史修订是三个不同概念。例如教师拥有试卷，不意味着拥有引用材料；成绩当前指针改变，不意味着旧评分或旧结果被删除。

2. 知识、学校与课程

聚合或事实 保存内容 不应被误解为
IdentityUser / KnowledgeLibrary 原账号与默认个人库归属 学校拥有教师账号
KnowledgeItem / KnowledgeVersion 条目整理信息、正文版本与当前发布指针 分享后所有私人修订都公开
KnowledgeAttachment 版本附件元数据与 Blob 引用 独立于版本的永久公开 URL
KnowledgePermissionScope 企业知识的显式访问策略 教育学校成员或任教关系
SchoolKnowledgeShare 指定版本、学校、用途与冻结共享元数据 所有者转移或任意衍生用途授权
KnowledgeIndexJob / KnowledgeChunk / KnowledgeEmbeddingRecord 索引执行、可追溯分块、模型及向量映射 Qdrant 中存在就已完成或可读取
SchoolMembership 某账号在学校的 Teacher／Student／Manager 身份区间 当前具体任教或在班
TeachingAssignment / StudentEnrollment 学期、班级、学科与有效关系 允许跨校查看全部历史
教材、章节、知识点修订、映射 稳定结构和不可变课程引用 自由文本“数学”标签即可替代

成员和关系使用 UTC 半开时间区间，结束旧关系与建立新关系保留历史。资料的自由标签用于个人整理；教材范围需稳定编号、版本、章节和明确映射。

3. 资料上传、发布与索引

  1. 用户创建条目和草稿，上传附件；服务端核对账号、版本归属、文件限制与草稿状态。附件实际写 Blob，主库保存引用。
  2. 发布命令提交完整访问策略。服务端校验规则不混用、不重复，在一笔关系型事务中更新策略、当前版本、适用的旧索引状态并插入待处理任务。
  3. 有效指定版本共享可以保留旧发布版的索引；私人新版本不扩大共享。是否保留索引和谁能读取是两次独立判断。
  4. Host 轮询任务，调用 KnowledgeIndexJobProcessor，处理顺序是 reader → processor → chunker → persistence → embedding → vector-store。
  5. reader 读取正文／Blob，非文本格式走 MarkItDown；转换后的正文和分页信息被处理和切块，分块保存业务编号与内容 hash。
  6. Embedding 通过模型目录选择模型与维度，调用网关，保存追踪记录并 upsert Qdrant。成功完成全部阶段后才能标记 Indexed。
  7. 自动重试留在同一任务并退避；人工重试／恢复创建关联原任务的新任务。旧任务仍用于追溯。

失败时不把 UI 的“发布成功”解释为可以检索。当前长事务与旧向量清理缺口详见审计 3、4；本图的功能顺序是现有实现，推荐的短事务执行方式尚未改入代码。

源码：KnowledgeItemAppService、KnowledgeIndexJobProcessor、Ingestion、Embedding。

4. 权限感知 RAG

RagAnswerService 首先验证问答功能权限并选择模型。检索器从当前服务器身份构造范围，检查请求中自报的 UserId／TenantId 不得冒充其他主体，再计算可用共享版和课程分块。

Qdrant 根据租户、所有者／组织、共享版本、课程候选、安全等级和发布标志缩小候选。返回的向量命中只提供候选编号和相似度；检索器批量回读条目、版本、分块、策略与索引事实，并重新检查当前学校共享和成员关系。

其中共享访问要求分块所属任务为 Indexed；当前发布版本的直接访问按分块有效性、版本生命周期和权限判断，没有同样的任务完成状态门槛。这是当前实现的路径差异，本轮未以真实故障注入验证部分索引写入时的表现。

只有通过检查的正文进入模型提示。无可用上下文时返回“知识库依据不足”；模型失败有受控降级。回答附引用，审计保存 hash、受控摘要、引用编号和模型信息，不以日志保存完整 prompt 作为调试方法。

共享撤回后数据库复核阻止新的使用，但已经看过、下载过或正在处理的内容不能被承诺“从用户记忆中收回”。D03 已明确学生材料停止后续在线读取，历史答卷与已上交副本由独立授权保留。

源码：KnowledgeRetriever、RagAnswerService、KnowledgeSourceAccessGuard。

5. 备课、出题、审核与试卷

教师先选择有效任教和教材范围，关联允许使用的本人资料或学校共享版本。LessonPreparation 保存目标、教材映射、资料版本和题卷引用的修订；备课反思必须经明确动作才复制为本人知识草稿。

AI 出题保存独立生成任务，worker 认领并恢复记录的账号上下文，重新检查权限和来源。调用模型产生候选；教师编辑、采纳、评分规则确认和审核均不被生成完成代替。候选或来源变动会触发相应的重新核验。

ExamPaper／ExamPaperQuestion 冻结题干、选项、评分定义、知识点和来源快照。教育任务引用这个冻结试卷，学生作答与评分不跟随教师后来的题库编辑。

企业旧 ExamPlan 与教育 EducationAssessmentTask 是两套运行模型。它们共享部分试卷数据，但发布、名单、答卷、评分和开放规则不同；不能将旧企业考试的分数直接当成教育统一成绩发布结果。

保存 ResponseRevision、CurrentResponse 题目属于冻结卷；原操作回执；答卷版本冲突；图片引用属于本次作答
交卷／截止 Submission manifest 列出所有题，包括未答；固定确切响应修订及 hash，不读取后续答案
初始化／批改 QuestionGrade、GradeRevision 自动分与人工分分开；老师草稿与确认指针分开；不覆盖人工处理
全任务封存 Closure 所有固定接收人分别是已封存提交或缺考；缺考不是 0 分答卷
最终发布 ResultRelease、ReleaseItem 全部有效提交的每题完成确认评分；冻结每份答卷对应的确切评分修订
学生查看 当前结果发布投影 隐藏／仅分数／完整讲评，分别裁剪字段；到开放时间且当前关系有效
改分／复核 新评分、替代发布、ReviewRequest 原因留存，结果指针与新分数一起切换，保留原版本

教育写入遵循学校 → 当前账号 → 任务／答卷／评分根的约束顺序，避免撤权与写入各自成功。后台评分按已记录的租户与封存事实计算，不凭后台身份授予阅读权。

学生明确提交前看到的是已保存答案和上传事实的预览；预览指纹用于发现之后的变化。只在有明确排除／确认时处理未同步或未答部分，不能由客户端显示状态假报服务器保存。

源码：测评服务、封存处理器、评分处理器、结果发布、ADR 0017。

7. 学情、成长与个性化教学

评分证据覆盖所有题目，不能只收集错题。知识点得分分配保持总量一致；同题练习、答案提示、实际材料提供和教师核验都影响证据资格，不能直接把“做对了”解释为独立掌握。

学校学科规则有明确版本；报告固定任务、窗口、课程、学生和来源指纹。worker 计算时保存租约与运行编号，完成前重新捕获来源，变化则停止旧计算或等待重算，不将过期结果冒作最新事实。学生成长只使用本人已经开放的正式结果。

人工或 AI 生成方案都是老师私有初稿。AI 请求投影移除学生身份和原始答卷／私有观察，仅传必要的学科、知识点状态与时间安排；返回 JSON 经结构和业务限制检查。教师明确保存、确认和下发后，学生才看到公开版本。

方案正文、执行决定、活动进度、材料读取、正式测评、困难反馈和教师私有处理分别建模。暂停阻止新的活动执行；已开始的正式考试仍按其原窗口封存。新题复测有正式任务关联，活动自报“完成”不能自动生成掌握证据。

源码：报告处理器、AI 方案执行、方案执行控制。

8. 微信身份与客户端恢复

网页先验证原账号密码，签发随机、短时、服务端只保存 hash 的绑定码。小程序将绑定码和一次性微信证明交给服务端核验后建立绑定；登录再使用新微信证明取得短时 token。绑定本身不创建账号、学校身份或私人资料归属。

每次带微信绑定 claim 的业务请求核对 token 有效性、账号、租户、绑定、应用配置及账号安全戳。本人解绑释放活跃唯一键，保留历史，后续请求会被拒绝；不承诺召回已经在执行中的请求。

原生 session.js 管理登录和身份代次，迟到响应不能恢复旧账号投影。token 保存在内存；本地绑定元数据不是授权凭证。不同业务的恢复状态有区别：

  • 私有评语、关系申请等通常只持久化操作编号和必要范围，正文留在内存。
  • 正式作答、订正、复练等可在用户知情后保存本机草稿，按身份和确切版本隔离。
  • 网络失败是“结果未确认”，先查询同一操作的回执；不自动创建新业务事实。
  • 临时文件按当前身份跟踪，退出和拒绝尽力清理；共享设备上系统级副本、相册和无法清理的文件仍需真机政策验收。

源码：绑定服务、证明核验、请求中间件、session.js。

9. 通知、正文、私有观察

学生统一收件箱接入测评、评语、方案来源，按当前学校和来源权限查询。消息仅携带通用种类、公开编号、确切版本、可用时间与首次消息已读；不放分数、答案或教师私有原因。

打开消息不自动开考或读取正文。真正进入来源时再次检查当前版本和权限；旧版、撤回或失效的来源不能悄悄换成新版本。评语的消息已读与实际正文已读分别记录。真实微信投递尚未配置，站内记录成功不能显示为微信发送成功。

教师观察与对学生评语分开保存。把一条观察用于评语需明确选取或复制；学校管理员和学生不会因能看到评语而读取教师观察原文。

4. 恢复顺序

  1. 恢复 PostgreSQL 事实和对应 Blob 备份，核对附件引用、版本、提交和结果指针。
  2. 根据原任务与操作编号处理未完成状态，避免把未知响应当成未执行而重复发布或生成。
  3. Qdrant 可重建，但模型维度、collection、当前版本、有效学校共享和权限必须重新核对。
  4. 已有正式考试保存、交卷、人工批改应能独立于模型服务继续执行。停止模型不等于停止数据库或 Blob。
  5. 多 Host 上对未知旧执行者的产物清理需要运行隔离；不能为了删临时文件而误删仍在写入的产物。

仓库目前不应承诺任意 RPO／RTO。D09 尚待确定备份恢复点、恢复时间、同时开考人数和图片负载；图中的恢复顺序是架构说明，本轮没有执行备份恢复演练。

6. 最小后续验证建议

修复答案覆盖后，用两条乱序保存验证新答案保留；修复超时恢复后，验证计划仍开放且允许两次时能得到新的有效尝试。修复向量回收后，用多个历史代次高分旧块挤占候选的场景验证有效召回。

索引事务修复应使用两个数据库连接：一个让模型替身阻塞，另一个查询已提交心跳并尝试恢复／撤回；随后确认失效执行者不能完成任务。此用例比再增加很多只检查状态字符串的单元测试更有价值。
