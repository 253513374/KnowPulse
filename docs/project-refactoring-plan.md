# KnowPulse 项目改造计划

日期：2026-10-23；版本：v1.0；状态：实施中（2026-10-25 教学核心闭环已真实验证，后续阶段仍按本计划推进）。

业务依据：[教师出题与学生答题业务文档 v1.2](business-requirements.md)及 [领域词汇](../CONTEXT.md)。代码核对基准为 Web／后端 `31c5e6f`、小程序 `b1a041b`。

**改造目标：复用现有资料处理、出题和答题评分能力，将企业知识学习系统收口为教师工作后台与学生答题小程序。先建立教师数据归属和学生访问边界，再逐段接通业务，最后退出旧入口及清理无用实现。**

本计划保留 2026-10-23 的规划基线，当时只整理计划、未修改代码。2026-10-25 已按后续授权启动核心闭环实施；当前实际完成项、验证证据及未通过门槛见[教学核心闭环实施与验证](teaching-core-verification.md)。下文验收项仍是逐项实施门槛，不代表全部通过或已经上线。

## 1 改造边界

### 1.1 必须遵守的已确认规则

- 教师使用个人知识库与获授权共享资料出题，学生通过小程序答题。
- 教师发布任务时指定接收学生；学生打开小程序即可看到待答任务，首期不做微信消息提醒。
- 同一学生可以关联多位教师；每位教师只能查看自己发布任务产生的作答结果。
- 新加入学生不自动接收历史任务，师生关系和任务指派分开保存。
- 不建设学校管理，不要求教师身份证、资格证或任职认证；正常登录和数据权限继续保留。

### 1.2 处置含义

| 处置 | 本计划中的含义 |
| --- | --- |
| 保留 | 继续复用既有实现和必要保障，补齐新业务需要的授权及测试 |
| 调整 | 改变业务归属、规则、接口或用户操作，优先在现有模块内完成 |
| 移除 | 从新教学产品的界面、路由和正常调用链退出；代码及数据是否删除另按清理条件判断 |
| 后置／不建设 | 不纳入本轮改造；尚未实现的学校、认证等能力不能被写成待删除的既有功能 |

同一模块可以保留底层实现，同时调整产品行为。例如保留考试评分与快照，调整为面向指定学生的答题任务；不要求重新建设另一套作业引擎。

## 2 功能保留清单

| 编号 | 保留内容 | 处理边界 |
| --- | --- | --- |
| K01 | ABP 分层结构、账号登录、功能权限及既有租户隔离 | 不换技术栈，不重建权限框架；教师归属是另一个业务边界，不能简单把每位教师做成一个租户 |
| K02 | 资料上传、正文、附件、版本和存储 | 复用现有知识资产；所有权及共享规则按 A01、A02 调整 |
| K03 | 文档转换、分块、索引、失败重试和恢复 | 隐藏技术过程，不删除执行保障；真实处理完成后才显示可出题 |
| K04 | AI 检索出题、候选题结构校验和来源记录 | 增加选定资料的强约束；模型失败或没有依据时明确失败，不自动发布题目 |
| K05 | 人工编辑、题目合法性校验、确认后可用的状态约束 | 复用现有草稿和确认基础，压缩教师操作，不强制多人审核 |
| K06 | 固定选题、试卷及评分规则快照 | 修改题库或原资料不能改写已发布任务和历史成绩 |
| K07 | 服务端保存答案、本人作答校验、幂等交卷、客观题评分和错题记录 | 移除学生端正式本地计分，保留正确性及数据恢复能力 |
| K08 | 数据备份、关键操作记录、必要的模型和文件处理维护能力 | 留给受控维护入口，不成为教师日常出题的前置步骤 |
| K09 | 原生微信工程、现有样式和答题交互 | 保持独立仓库，复用组件和资源；页面及数据源按学生流程调整 |

## 3 功能调整与必需补齐项

| 编号 | 当前情况 | 目标调整 | 主要阶段 |
| --- | --- | --- | --- |
| A01 | 知识、题目、考试主要按租户及功能权限管理 | 建立教师业务所有权；查询、直接 ID、下载、编辑、删除、生成任务和结果查询均遵守归属约束 | P1 |
| A02 | 企业上传引导默认全员可见，历史空范围也可见 | 新个人资料默认私有；自用处理完成与向其他教师共享分开；无归属历史数据不能自动公开 | P1、P2 |
| A03 | 有授权检索，出题范围主要是自然语言描述 | 教师选择具体个人／共享资料；服务端只取所选、获授权、可用版本的交集，检索与引用均受约束 | P2、P5 |
| A04 | 题库分草稿、审核队列和正式题目等多个入口 | 收为教师自己的出题与题库工作区；本人检查、编辑并确认，保留候选题不能直接发布的规则 | P2 |
| A05 | 没有完整教师学生名单及多教师关联业务 | 补最小师生关系；邀请、申请及教师确认方式按业务文档建议，在实施前确认 | P3 |
| A06 | 考试分配支持指定用户，但空分配可默认全员 | 发布时复核本人有效学生，拒绝空名单；“我的全部学生”也展开为当次具体名单，不能动态补发 | P3 |
| A07 | 以考试时间、时长、次数等参数组织发布 | 固定选题发布轻量答题任务，不强迫练习填写正式考试参数；不靠虚构超长时间模拟无限时 | P3 |
| A08 | 考生 DTO 会映射标准答案、解析和内部来源，结果策略未充分裁剪 | 学生响应只含当前阶段允许展示的数据；查看任务、开始、恢复、交卷和结果接口全部检查 | P1、P4 |
| A09 | 存在答案保存、评分和作答恢复，但过期恢复等边界有缺口 | 明确继续与重做的区别，修复过期进行中作答恢复；按最终次数和展示规则返回结果 | P4 |
| A10 | 管理列表和成绩筛选不等于教师归属隔离 | 教师只看本人任务及对应学生结果；统计人数使用固定接收名单，不使用当前学生总数 | P1、P4 |
| A11 | 小程序是员工学习原型，依赖演示数据和本地状态 | 接稳定学生身份、多教师关系、真实待答任务、答案保存／恢复、交卷和服务端结果 | P1、P4 |
| A12 | 企业菜单、技术维护入口和业务步骤混合 | 收为“我的资料、共享资料、出题与题库、我的学生、答题任务”；分类标签合入资料编辑，结果从任务进入 | 随各阶段落地，P6 收尾 |
| A13 | 有企业可见范围，但没有完整共享使用语义 | 区分共享读取／出题与原件修改；取消共享限制未来使用，不静默删除历史任务或成绩 | P5 |
| A14 | 公开入口可直接把索引任务标为完成 | 收紧为真实处理结果驱动，检查学生／教师接口不能绕过处理流程制造“可出题”状态 | P2 |

A01 不能只在页面加“我的”筛选：资料的版本、附件和分块，AI 任务及候选题，题库、任务、指派、作答和结果都必须沿其业务归属授权。教学账号也不能通过旧通用接口绕过新限制。

## 4 功能移除与后置清单

### 4.1 从新教学产品移除

| 编号 | 退出内容 | 后续处置 |
| --- | --- | --- |
| R01 | 教师必须配置部门、岗位、职级、用户组织关系和企业安全等级的流程 | 从教师导航和必填步骤退出；先解除教学依赖，再决定是否清理旧实现 |
| R02 | 员工学习路径、必学／推荐知识、阅读打卡和成长计划 | 新学生流程不再调用；历史学习记录保留，旧企业兼容范围确定后再清理接口 |
| R03 | 学生小程序的知识库搜索、AI 问答、知识原文阅读入口 | 从学生导航、路由注册和相关调用移除；不能用隐藏按钮代替资料访问限制 |
| R04 | 教师必须经专职编辑员、审核员流转的界面流程 | 合并为本人确认；保留后台校验和状态约束，不让未确认 AI 题直接发布 |
| R05 | 教师日常必须操作模型目录、索引阶段、提示模板、调用日志和评测的入口 | 从教师工作区退出；必要功能保留在受控维护入口 |
| R06 | 学生正式流程中的本地演示身份、固定题目、模拟进度和本地评分 | 用服务端数据替换；需要保留的演示内容移作测试夹具，正式包不能携带可泄露答案的夹具 |
| R07 | 重复建设 Web 学生中心和小程序学生中心的计划 | 学生体验以小程序为目标；旧 Web 答题／学习页面是否兼容由历史使用情况决定 |

### 4.2 不建设或后置

不建设学校档案、学校组织、教务、学籍、教师实名和资格认证。首期不做微信消息推送，也不额外建设消息中心。

复杂随机组卷、专职多人审核、完整限时考试、复杂防作弊、更多题型与主观题计分、跨任务运营分析和完整 BI 后置。教师知识问答可作为备课增强，不能阻塞资料出题与学生答题闭环。共享题库和公开资料广场不因这次改造自动加入范围。

### 4.3 不能直接删除的旧依赖

组织和安全等级目前仍被知识访问上下文、可见范围判定、向量过滤、岗位适用题目、考试／学习分配、EF 映射及测试引用。它们可以退出教师业务操作，但不能先删表、枚举或判断分支。

真正删除旧页面、服务或表之前，必须完成调用与数据引用调查、新流程替代、历史兼容决定及回归验证。只删菜单而保留可被教学账号调用的宽权限接口，也不算完成退出。

## 6 实施顺序

建议采用以下顺序，不预设未经评估的工期。每个阶段先通过对应验收，再扩展下一段。

| 阶段 | 交付目标 | 依赖与完成门槛 |
| --- | --- | --- |
| P0 范围与迁移准备 | 确认待定规则，清点旧用户、资料、题目、考试和权限，列出归属映射与兼容范围 | 涉及既有数据的归属不清时，禁止直接按上传人或当前角色批量授权 |
| P1 身份与访问基础 | 教师／学生身份边界、教师所有权、默认拒绝的访问限制、学生响应保护 | 两个教师和多个学生账号完成跨用户拒绝访问；旧接口不能绕过新边界 |
| P2 个人资料到教师确认题目 | 私有资料上传处理、所选资料出题、本人编辑确认、教师题库 | 一位教师可用自己的资料完成一组可发布题目；另一教师不能读取或修改 |
| P3 师生关系与定向任务 | 多教师学生关系、有效名单选择、固定选题发布和持久指派 | 空名单拒绝；只选两名就只生成两名收件人；新增学生不出现历史任务 |
| P4 学生真实答题与教师结果 | 小程序身份、待办、保存恢复、交卷、个人结果和教师任务结果 | 完成真实端到端流程，重复提交不重复计分，教师结果严格隔离 |
| P5 共享资料闭环 | 显式共享使用、所选共享资料出题、取消共享后的边界 | 两位教师完成授权与未授权对照测试，原件不被使用者修改，历史快照不被重算 |
| P6 入口退出与发布验收 | 收口菜单和旧路由、处理兼容与迁移、更新文档并完成微信验收 | 验收矩阵通过、无旧权限绕过、迁移可核对且具备恢复方案后再发布 |

P2 与 P3 的师生关系部分可在 P1 的稳定身份和边界确定后并行。P5 可在权限及资料选择契约稳定后并行准备，但不能推迟到“完整范围已交付”之后。任何真实学生试用均应晚于 P1 保护及对应的 P3、P4 访问校验。

### P0 先确定影响实现的规则

仅补齐实际影响后续开发的分界：共享对象及撤销规则、邀请确认及显示名称、作答次数和结果展示、历史企业兼容范围。是否无限时及任务发布后如何停止接收，也应在改造旧考试参数前明确。

“默认全员可见”与教师个人资料默认私有冲突。实施前重新记录 [ADR 0002](adr/0002-default-guided-upload-visibility.md) 的替代决定及历史处理，不直接改写旧决策的历史语境。[原子发布](adr/0005-atomic-knowledge-publish-with-explicit-access-policy.md)与[可靠索引](adr/0006-recoverable-knowledge-index-job-execution.md)的一致性保障继续复用。

### P1 访问基础先于页面换名

归属控制覆盖列表、详情、修改、删除、附件下载、生成任务与结果。教师只能使用本人或获授权共享资料，学生只访问获指派任务及本人作答。未经确认的历史数据不进入新教师的可见范围。

落实学生安全响应，检查所有会嵌套返回试卷的位置。开始或恢复作答时，正确答案、提前解析、内部来源和私有原文不得返回；结果阶段按确定规则展示。不能仅在小程序把字段藏起来。

### P2 先交付能用的个人出题流程

教师上传自己的资料，看到处理中／可用／失败，选择具体资料出题，编辑并确认，再进入自己的题库。资料处理、检索范围及 AI 来源校验必须真实执行。保留人工补题，避免整个后续答题联调被模型可用性阻塞。

教师界面随此阶段收口，不要求先完成全站视觉重做、完整运营控制台或复杂题库管理。

### P3 接收名单在发布时固定

师生关系只影响未来可选学生。发布时再次检查关系有效性，将“全部我的学生”转换为当次具体名单，并一致保存任务、题目评分快照和全部指派；任一步失败都不能显示完整发布成功。

新教学路径必须去掉“空分配转全员”和“无指派视为全员可参加”的兜底。邀请或转发链接不能自动新增某份任务的接收人。

### P4 用真实服务替换演示答题

复用 `exam` 页面完成详情、作答和结果；实现登录失效、保存失败、退出重进、重复交卷和错误恢复。正式成绩由服务端计算，任务状态和已保存状态以服务端结果为准。

教师在任务内查看接收名单和结果，先验证“教师甲看不到教师乙任务结果”，再增加简单统计。不以可选的任务 ID 或学生 ID 筛选代替教师归属授权。

### P5 共享是资料使用权

共享对象和撤销策略确认后，沿用同一资料检索和出题流程。使用者可以基于授权资料出题，不能修改分享者的原件；生成题目进入使用者自己的题库，不反向授予分享者查看其学生结果的权限。

撤销共享后阻止新的读取与出题；已发布任务和历史成绩保留。既有题目能否再次发布，按最终确认规则处理，不能在实现时自行选择。

### P6 先退出调用链 再做删除

同步收口教师导航、小程序注册、旧页面跳转、角色权限、种子数据和测试断言。必要维护功能移出教师正常流程，旧接口对教学角色的访问限制必须同时检查。

先证明旧功能没有教学调用者，再根据兼容决定删除无用实现。数据库表、历史记录与迁移历史不跟随菜单删除。发布前完成真实微信环境“收到任务→作答→交卷→结果”和跨教师验证。

## 7 数据迁移与发布安排

1. **先清点与备份。** 记录数据量、当前归属线索、权限范围、附件和索引状态，验证备份可恢复后再计划迁移。
2. **先新增边界 后迁移归属。** 教师归属、师生关系和具体接收人以可核对的业务映射建立；`CreatorId` 是线索，不是自动归属授权。无法确定的记录留在受控历史范围，不默认为公共库。
3. **不要自动补历史关系。** 不根据同名、同部门推断师生关系；也不把旧“全员考试”批量转成所有新学生的任务。历史答题、成绩和快照保持可追溯。
4. **权限变化联动索引。** 资料归属／共享改变后更新相关索引，检索仍以当前授权二次复核；旧向量快照不能扩大可见范围。
5. **两个仓库分步发布。** 后端先提供并验证兼容接口，再发布学生小程序；不能假设两端能同时更新。版本不匹配时明确提示，不回退到本地计分或全员访问。
6. **失败时保留记录。** 回滚方案优先暂停新入口／新发布并保持已提交答案、成绩可恢复；不得用删除新数据或直接回退表结构代替回滚评估。

本计划不授权删除历史企业数据。只有兼容范围、保留要求、替代流程和恢复方式明确，且调用检查无遗漏时，才安排实际删除旧实现。

## 8 验收与测试安排

准备教师甲、教师乙；学生一关联两位教师，学生二仅关联甲，学生三在甲发布任务后才加入，再准备未获授权账号。用这些身份跑同一组真实流程。

| 验收项 | 必须看到的结果 |
| --- | --- |
| 教师资料隔离 | 乙不能通过列表、ID、附件或 AI 检索读取甲的私有资料，不能修改甲的题目或任务 |
| 指定资料出题 | 候选题依据只来自教师勾选且有权使用的资料；无授权或处理失败时不产生假成功 |
| 本人确认 | 未确认候选题不能发布，教师本人可完成确认，不需要专职审核账号 |
| 多教师关系 | 学生一可以分别收到两位教师的新指派；重复加入不产生重复有效关系 |
| 固定接收人 | 甲仅选学生一和二时，只有两人收到任务；空名单拒绝，学生三加入后不出现该旧任务 |
| 学生访问与答案保护 | 非接收人不能借链接或改 ID 作答；开考响应不带标准答案、提前解析及私有来源；学生只能操作本人答案 |
| 保存恢复与幂等 | 断网或保存失败不显示假成功；重进恢复已保存答案；重复交卷不增加正式结果 |
| 结果隔离 | 甲只看甲的任务结果；学生一的乙教师任务不会出现在甲的查询或统计里 |
| 共享使用 | 乙获授权后可据甲共享资料出题，不能修改原件；撤销后按规则阻止后续取用 |
| 历史稳定 | 修改资料、题库、名单或共享状态，不静默重算旧任务和成绩，不自动补发给新学生 |
| 页面与运行 | 新学生入口无旧学习／知识库／问答残留；真实微信环境完成交卷和结果，首期不依赖推送接口 |

未来实施时优先复用现有 xUnit、Shouldly、NSubstitute 和 Node 内置测试。保留发布一致性、权限检索、题目校验、评分和幂等测试；替换固定企业默认全员、五个 tab、学习演示数据等不再符合目标的断言，不通过直接删测试来掩盖未迁移调用。

按变更阶段运行对应领域、应用服务和 API 契约测试；小程序运行 `npm test`，随后做真实微信交互验证。最终再运行解决方案构建和测试、必要的 PostgreSQL／文件／索引集成验证。旧文档记载的历史通过结果不能作为本轮改造的验收结果。
